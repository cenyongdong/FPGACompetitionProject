# 去除诊断、保留异常消费的 HDMI 候选

2026-10-26 用户要求检查此前完成稳定性测试的位流，移除检查探针及协议检查 IP，保留异常消费缓解手段，执行多轮、每轮 5 分钟的完整链路稳定性测试。

后续现场补测：用户到达板卡旁后，r2 复用同一 BOOT／程序完成 300 秒运行，2981 次推理、2980 次 HDMI 采纳和 PC 接收，1 个过期结果丢弃；用户明确确认“画面正常，内容持续更新”。正常停止、STOP 与帧缓冲释放确认通过，无新增内核日志；[精确结果及现场确认](../../../tools/pose-v1/evidence/hdmi-probe-free-drain-20261026-r2/board-summary.json)。

r3 第 1 轮按键后 SSH／ping 不通，事后 90 秒串口无输出。PL_KEY1 对应 `sys_rst`，不是 PS 上电复位；没有取得正常 STOP／帧缓冲释放证明，不能由这一按键样本认定 D45 启动故障重现。用户完整断电重启后，原 BOOT、全新启动编号、FPGA operating、无旧进程及无设备占用均已核验，再执行后续独立测试。运行中 PL 复位自动恢复仍未解决，不能以另外两轮通过覆盖此失败。

r3 第 2 轮则在 **SDK 之前实际触发了保留的异常消费**：初始 flags=`0x1008c`，PS／S01 返回有效；一次有界消费后 status=`0x02050082`，解码为 16 拍、80 个 HP 周期、QUIET 终态、见到 RLAST，未标记响应错误、错误 ID 或迟到返回。SDK 前静默复查保持相同终态，随后完成整轮真实链路。此为本候选新增的实板消费缓解成功样本，不是 D45 根因已修复或运行中按键恢复通过。

r3 后两轮原生退出码均为 0，取得 STOP／帧缓冲释放证明，无新增内核日志和残留设备占用；CSI 对齐恢复 5／6 次，最长结果间隔 3.152／3.218 秒。异步归档丢弃 603／713；第 2 轮 PC 发送 2725、接收 2724，连接前丢弃 4，未宣称零丢帧；两轮 PC 无无效或重复帧。实际共 3 次候选、3 次 SDK、2 次原 BOOT 回退（首轮用户完整断电，末轮正常软件重启）。最后原 BOOT 启动编号为 `7170b447-f844-421f-b5d6-36140b450e1a`，三包全部关闭、余额为 0、本批板端及本机观察进程均已结束。r1／r2 不复活旧额度。

基线为完成 r5／r10／r11／r12 有限实测的 r45；它仍包含事件／读通道监视器、启动见证、周期记录器和 AXI 协议检查器。历史 `probe_free` 候选误删了消费器并发生 SDK 初始化 DMA 失败，本轮不沿用该候选功能设计，也不改写其失败记录。其已通过时序的物理检查点只用于新设计的增量布局参考。

本覆盖层删除所有上述被动诊断和 `MARK_DEBUG` 属性。`hp2_startup_drain.sv` 与 r45 保持逐字节一致，仍为配置后一次启用、256 拍／4096 HP 周期／64 空闲周期边界，保留请求冲突、错误 ID、复位及迟到返回的处理。消费器不能复位业务接口、发起读写请求或启动 HDMI。控制接口只保留命令／确认、消费状态和操作必需的当前电平，删除协议检查器状态、重武装、时间戳和历史存储；ABI 改为 `0x48444302`，地址保留 `0x400b0800`。PS 端请求有效信号也参与消费碰撞禁止。

配套软件配置为 `POSE180_DEMO_PROBE_FREE_DRAIN=ON`。在 SDK 前，原生 32 位 MMIO 检查新 ABI 和一次性状态；空闲无返回时不启用消费，有符合条件的 S01 返回时才允许单次消费，终态及静默复查通过后进入 SDK。消费控制读写不属于被删除的被动诊断。保留实际 HDMI 所有权、错误处理、tagged STOP 和排空证明；模型、SDK、预处理、AI 四路及频率不变。移除协议历史后不再声称具备原检查器的诊断覆盖，也不以该工作关闭 D45 根因。

本轮工作目录为 `.local/hdmi-probe-free-drain-20261026-r1`；原生命令、完整日志、仿真和物理资格统一保存在 `tools/pose-v1/evidence/hdmi-probe-free-drain-20261026-r1`。整机综合、7 组控制仿真、9 组消费边界仿真、ARM64 编译和完整物理资格已完成。最终 setup WNS +0.030 ns、hold WHS +0.012 ns、TNS／THS 均为 0，85378 条可布线网络全部完成，内部无未约束端点；仅保留既定 AI 两项最小周期例外及既定 GT 适配范围，不宣称原始报告全部为零违例。最终报告为 `physical-final`，检查点为 `pipeline-scoped.dcp`。旧 GP 数据路径检查曾把时钟树可达误判为数据可达；修正实际数据扇入筛选后通过，原始失败保留。消费器原有时序范围和当前状态的 5 ns 约束均已核验。
