# r51 static-background overlap

Only prepare_background() runs before hdmi_gate.take(): it copies immutable static pixels into an independent owned 4,147,200-byte buffer and never accepts scores/poses. All finite checks, candidate selection, projection, dynamic text/skeleton painting and SDK calls remain after Host archival ACK and the existing numeric gate. A failed publisher wakes take(); the prepared vector is then ordinary stack-owned memory and is destroyed by unwinding. No queue/SDK thread, handoff protocol, model/math/NPU, 20ms input or 200ms adoption deadline changes.

The r47 main remains untouched; joint/ is its new copy. render_rgb565_ms retains total CPU-render scope by summing preparation and dynamic durations, excluding the overlapped gate wait. Added prepare_background_ms/render_dynamic_ms sidecars distinguish phases; existing other timings are unchanged. Original render(scores,poses,id,status) calls the same private implementation without a prepared buffer and keeps its old timing scope and pixel algorithm.

Compile cpu_regression.cpp + joint/projection.cpp + software/core/display/hdmi_renderer.cpp as C++17 Release with -ffp-contract=off and include software/core/display. No SDK link is required for this CPU executable. Run renderer_overlap_bench FIXTURES GOLDEN_CPU_OUTPUT, where GOLDEN_CPU_OUTPUT is the preserved E47 cpu-evidence.tar.gz cpu-output directory (native-308/309/310.rgb565). The three Result frame IDs are1000000/1000010/1000020. NoInput/Stopped additionally compare the old public API and the prepared API. This source-only change has not built or run the benchmark.
