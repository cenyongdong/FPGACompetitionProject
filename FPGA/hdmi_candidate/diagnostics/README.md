# AI数据通路被动观测

用于定位HDMI候选下PL-DDR参数上传异常。模块只接收既有握手和数据低位，独立CSR只控制快照，不驱动AI、DDR、HDMI或功能复位。新增扇出仍可能影响物理实现；它是诊断工具，不是故障修复。

source为200MHz hp_clk／pl_itf_clk，CSR为100MHz gp_clk。两域分别采用异步置位、三级同步释放复位。请求、确认各经两级ASYNC_REG同步；源快照保持至下次请求，接收域看到同步确认后才锁存。保持总线须实证10ns最大延迟有效，不能被既有跨域false-path遮蔽。计数器32位回绕，周期计数在200MHz下约21.47秒回绕；只能按模差分析，不作为独立频率仪。

CSR基址0x400b0100（旧HDMI窗口仍为0x400b0000）：

| 偏移 | 契约 |
|---|---|
| 0x00 | 写1请求一次快照；读bit0 busy、bit1 sticky command_error。忙时或非法命令拒绝并置错；无清错命令 |
| 0x04 | ABI 0x41494401 |
| 0x08／0x0c | 请求／完成代数，成功快照后必须匹配 |
| 0x10 | 快照24个32位字 |
| 0x40—0x9c | 以下冻结快照，按字索引读取 |

| 字索引 | 含义 |
|---|---|
| 0／1 | PL合并AW数据握手／其中末拍握手 |
| 2／3 | PL B响应握手次数／BVALID周期 |
| 4 | MIG写命令握手 |
| 5／6 | MIG WDF数据握手／其中末拍握手 |
| 7／8 | MIG读命令握手／读数据有效周期 |
| 9／10／11 | PL AR握手／R握手／R末拍握手 |
| 12／13 | PL AW背压周期／MIG WDF背压周期 |
| 14／15 | DDR未校准周期／source时钟周期 |
| 16 | bit0 calib、1 ddr_ui_rst、2 app_rdy、3 wdf_rdy、4 awvalid、5 awready、6 awlast、7 bvalid、8 bready、9 rvalid、10 rready、11 pl_rst_n；其余保留0 |
| 17／18 | 最后PL AW原始地址／awinfo与末拍标志 |
| 19 | 最后已接受MIG命令：高3位cmd、低29位原始addr |
| 20／21 | 最后PL AR原始地址／最后PL AW末拍原始地址 |
| 22／23 | 最后PL AW数据低32位／最后MIG WDF数据低32位 |

地址单位遵循原硬件总线契约，不能直接当作字节地址或CPU指针。不同接口的计数单位未必相同，不能简单把两个计数相等解释为完整传输结束。

首次约束检查报出原始硬复位作为样本数据的CDC-1。新候选v2只把该样本的bit14:13保留为0，不改变功能复位，不增加false-path；原失败保留在hdmi-live-20261017-r2/monitor-constraints。

配套ai_dma_probe使用公开SDK；--with-monitor先读ABI再允许DMA，只在SDK原异常已保存后或全部往返通过后请求快照，始终复用同一Device。不在正常DMA之间插入快照，不重新Open／reset后冒充原现场。SDK异常保留可能在途分配并退出71；不自动重试或扩展为模型测试。板测必须使用已核验的候选身份和独立执行包，主机编译通过不代表实板通过。

## r23启动历史与复位见证

`ai_boot_witness.sv`是r9六边界读观测器的可选扩展，默认关闭。启用后仍保持旧ABI `0x41495201`、104字及ARM／FREEZE接口；CSR基址为`0x400b0400`。新模块只接收信号，不驱动功能总线或复位。从配置后的首个source时钟开始记录，ARM不清除历史；历史寄存器使用配置初值，设计上跨本地PL复位保留，物理效果须单独板测。它不能观测source时钟开始之前的事件。

以下19字与旧快照共用同一次FREEZE。字0—10位于相对偏移`0x014—0x03c`，字11—18位于`0x1e0—0x1fc`；其余旧寄存器不变。

| 字 | 含义 |
|---|---|
| 0 | 新扩展ABI `0x42545201` |
| 1—2 | source历史标志／周期低32位；字1高8位为周期回绕计数，溢出后不可还原绝对周期 |
| 3—6 | 配置后PS AR／PS R／HDMI AR／HDMI R原始握手累计，包含复位期间样本 |
| 7—8 | 首笔PS AR地址／管脚字 |
| 9—10 | 路径复位释放且DDR校准后首个PS RVALID管脚字／周期模2³²；记录的是VALID，不要求READY |
| 11—12 | 首笔HDMI AR地址／周期模2³² |
| 13—14 | GP合并复位／同步采样HP2 ARESETN的断言次数 |
| 15—17 | GP周期低32位／GP复位高电平周期／HP2复位低电平GP周期 |
| 18 | GP标志、回绕／计数溢出与已发布位；bit7为快照已发布 |

源域384位保持总线在旧FREEZE源边沿锁存，经旧确认同步后才发布；GP复位统计在发布边沿取样，两个时间切面应分别解释。GP合并复位是`gp_clk_rst`，并非直接测量F8焊盘；HP2复位经两级同步采样。正确按键是PL_KEY1／SW6／F8，按住期间禁止CSR访问。

板端`capture_boot_witness.cpp`只用只读映射读取已完成FREEZE的19字，先保存初始／完整原值，再检验ABI与代数；不加载SDK、不发ARM／FREEZE。主机`capture_boot_witness.py`负责解码。同一FREEZE下，启动累计握手减去104字窗口握手，可得到本次ARM及之前的累计；相关计数溢出时停止该推断。首事件时间只有32位模值，不能在运行超过一个回绕周期后擅自还原绝对发生时刻。构建及板测状态见[r23恢复入口](../../../tools/pose-v1/evidence/hdmi-boot-witness-20261019-r23/state.json)。
