# ADR_22：SDK 拥有双源搬运隔离与编码并发判别

日期：2026-10-10。状态：批准方案已实施；独立无 VPU／有 VPU 门检通过，模型坏块未复现，根因未解决。承接 [ADR_21](ADR_21.md)，保留旧失败和完整候选门禁。

## 现象、影响与假设

真实模型192索引暂存出现前一次数据复制同偏移的残留；失败时公开生产计数已经234，稍后两轮设备源正确。因此增加 wait-to234 在已观测的复制开始点不会产生等待。尚需区分模型生产／分配／布局与 SDK 连续搬运、UDMA 可见性及编码共享资源。

仅依靠输出最佳骨架、索引取整、重复一次复制或固定 sleep 会掩盖问题，不能作为本次修正。SDK 内部状态 mask0x5／0xA 和 UDMA 同步方向仍缺匹配硬件／厂商驱动定义；二进制存在锁和同步调用不等于已证明其语义。

## 决策与模块边界

新独立 `pose_scratch_copy_check`，不创建模型 Session、不执行 NPU forward。通过公开 Device.defaultMemRegion、Tensor.mallocOn／copyFrom／read 取得两份 SDK 拥有 PL DDR scratch，长度30240／16800字节。A 为7560个唯一有限小数，B 为4200个唯一精确整数，全部逐位比较。

模式／拥有字节／比较／保存为 SDK-free 模块；SDK 适配层只由主线程持有；VPU 负载封装独立工作线程，仅调用冻结编码模块。编码使用原两缓冲、prime2、NV12／H264／opaque cookie；SDK、模型、CPU 数学、BOOT、CMA 和原推理程序保持。

每对按 A→B 立即复制到新 Host CPTR 张量，立即拥有原字节后比较，不在对内加入等待。无 VPU 连续100对／30秒；有 VPU 先取得实际非空 capture，之后主线程独占 SDK、100对按200ms间隔／20秒，整体180秒／编码上限1000。正常 drain、LAST、归还、join 后销毁 SDK；异常保留原始拥有字节及两轮 SDK 晚源，再停止。

原 Host107 并未新执行：原主程序 ELF、402份非清单载荷及原主程序来源和 SDK 身份逐位相同，由独立审查绑定上一批107／12注册／59600 FP32证据。新 Native／ARM 契约测试分别实际执行，报告明确区分复用和新运行。

## 尝试及工具修正

- r1 的100对无 VPU 搬运通过，但 SDK 自然分配使 B 地址34336模64为32，与实际模型两源对齐不同。保留成功证据，未执行r1编码并发。
- r2 在两份源之间取得并保留32字节 SDK padding，核验范围不重叠、两源模64为0；不指定固定设备地址。r2只构建，未传输／板测。准备工具 Windows 默认GBK读UTF8失败，以明确UTF8和已生成内容逐位断言修正，保留失败。
- r2板测前审查发现第二份复制抛错时可能丢失第一份拥有字节。r3改为调用者持有Pair，保存可用槽位，不补造缺失数据；SDK存在时独立尝试两轮晚源。Native／ARM部分异常保存契约通过，未声称实际触发了硬件复制异常。
- 本机初版视频审查把SPS/PPS包计作图像而失败。按实际每包NAL分类修正审查器：1参数集包＋200图像包＋1空LAST；源程序／载荷／数据未改，板测未重跑。

## 实施、验证和解决结果

r3 scratch ELF `613f2dc1b28bc3864e61a490e961cbb0d640570e0d8fd2f6df3249eb3f17f946`；manifest `df830da9f8d221424363ec1d09fddde8a34f409e40140fa095695385efd870a2`，403载荷／85来源。原主 ELF `3f0ad06c…419f1e37`保持。

Native／ARM各10拒绝与47760字节拥有值／前次复制块／部分异常保存通过。r3无 VPU100对、跨度69.24394ms；编码并发100对、跨度19800.31428ms，合2388000 FP32比较正确。程序每对全字节memcmp通过，本机独立生成期望模式核验全部实际指纹及首末原始字节；没有把全部100对原始字节逐份落盘。

两源实际地址4096／34368、padding34336／32字节，共同合法PL DDR区域且不重叠。并发202 capture包含200图像／1参数集／1空LAST；主机解码200序号及实际输入／capture PTS全对应，36443字节码流。首次非空capture为参数集包；编码上下文在全部搬运期间存活，首图像捕获稍晚于SDK打开，不能写成SDK打开前已有解码骨架。所有画面为合成NoInput，不计推理吞吐或视频模型验收。

三阶段均exit0、内核日志保持；200提交／200归还、正常LAST、两STREAMOFF、worker join、SDK销毁和端口释放完整。规整0，无清缓存／重启／配置变化。最终MemAvailable748928KiB、CmaFree29916KiB、普通512KiB折算单位35，仅现场，非永久首启动或泄漏证明。

## 结论、剩余限制与下一步

本批未在无模型生产者的同长度、64字节对齐 scratch 路径复现残留；不能宣布 SDK／VPU 无责、缓存同步已证或模型修复。scratch是固定1D布局C／低位PL DDR地址／独立分配；真实模型有实际merged分布、较高源地址、不同chunk／偏移、持续变化的数据及NPU生产，仍有多个差别。

下一新隔离候选先记录真实模型源／Host目标的合法区域对象、chunk、dtype／布局／分布、地址／偏移与生命周期，使用已拥有字节，不增加正常数据源读取或修改等待／copy／数学。之后根据实测选择能保持公开分配契约的更贴近模型对照。不把私有状态偏移、直接映射、零拷贝、cache helper或扩大CMA作为猜测修正；完整候选及原异常读回继续保留。
