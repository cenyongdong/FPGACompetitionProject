# ADR_37：真实 NPU 生产者完成契约与最小视图可执行性

日期：2026-10-11。状态：本轮有界审查结束，离线视图与官方部署日志已取得，硬件完成／根因未解决。

## 问题与范围

ADR_36 四项已知 SDK 写入对照通过，但 ADR_35 的模型首次 Host 坏片段未解决。锁、状态轮询和缓存同步存在，仍缺生产者写入与读事务完成的正式契约。

本批核对匹配公开头文件、文档、后端二进制及本地硬件资料；通过只读公开 NetworkView 审查单个生产者与原19成员融合组的输入、输出和指令边界。该审查程序不链接 XRT／后端，不读取 RAW 参数、不创建 Session／Device、不执行 NPU。

## 决策

禁止把公开 layerCount／握手名称或 Tensor ready 当作已证明的 DDR fence。原应用同步、CPU数学、模型、SDK、BOOT与异常读取保持。只有独立生产者的输入、指令、内存段、同步和参考能够闭合，才执行其硬件对照；无法保留原融合边界时按已批准方案停止最小生产者分支，不手改JSON或访问私有Session。

若缺匹配说明，记录可确认的检查路径及证据限制，形成本机责任证据包，不自行外发。全模型额外观察须明确它引入的读取及时间扰动，不能把未复现归为根因修复。

## 尝试与结果

六份ARM／Windows匹配公开头文件与ZG／XRT完整符号核对完成。匹配检查器比较layerCount与阈值，达标后有条件区域内memcpy，再进入PL→PL DMA轮询；HardOp有安装检查器／setReady(false)路径。未证明条件copy在当前输出实际发生或DDR完成语义。

XIR-only探针e51ea127…da1d47在ARM通过三视图，未加载RAW／Device／Session。8629与8631是零指令／零执行层Cast；原9186组19成员／11层，inputs486（FP32／400字节）、478（带填充FP16／17280字节），含Matmul8507权重。单Cast无法承担生产对照；完整组独立输入／参数／布局／参考未闭合，未硬件计算。

官方apply/log探针复用36冻结对象，不修改桥／CPU数学。r2程序8576af7f…5e1bbe7 exit0，实际两日志已产生；r3程序97641b15…40864be在新增门检误期待1而实际2时exit1，原错误与源码完整保留，无forward。官方主／memopt日志418328／56218字节已核验；8467／4386共址109232128、8479／4390共址109285376，全部is_ocm=false，与旧失败地址相同。不能由该部署快照证明失败瞬间私有映射／实际搬运或OCM根因。

本机首次rg查找受Git忽略影响，误判r2没有日志并错误推断父目录不足；原始档案证明已有两日志，该推断撤回。r3Host文件流目录契约通过，但不证明官方log方法有目录缺陷。两文件门检已在源码修正，r4程序7ec4e3cc…2e27b78仅编译，未传输或板测，不改写r3 exit1、不再重跑硬件。

FPAI缺codegen头与ISO C++17宏失败分别通过审查六运行时头／GNU++17修正；冻结旧头缩进告警局部处理不改其字节；传输前RAW路径／manifest字段假设修正，未发送旧包保留。错误检索、门检和修正是本机问题，不用作SDK数学／DMA故障证据。
