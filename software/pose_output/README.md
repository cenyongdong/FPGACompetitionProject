# SDK无关骨架网络输出

此目录提供最小拥有值契约和同步有界TCP发送器，独立CMake目标可在Windows/Linux构建。当前由PC文件回放程序驱动，未链接正式推理或HDMI主链。使用与实际验收见[PC观察台](../pc_viewer/README.md)。

## PIWPOSE1 / version 1

每条256字节，小端，显式逐字段编码，不将C++结构体内存布局当协议。TCP发送/读取次数不代表记录边界。IEEE754 FP32逐位保留，NaN/Inf及非法字段拒绝。

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0 | 8字节 | ASCII `PIWPOSE1` |
| 8 / 10 / 12 | u16 / u16 / u32 | 版本1 / 头长度88 / 总长度256 |
| 16 / 24 / 32 | u64各 | 会话 / 原始帧 / 推理调用号 |
| 40 / 48 | u64各 | 来源时间ns / 发布单调时间ns；未知为0 |
| 56 / 60 / 62 | u32 / u16 / u16 | 候选0..99 / 关节14 / flags：归档1、实时0 |
| 64 | FP32 | 原始候选分数，不增加发布阈值 |
| 68 / 72 / 76 | u32各 | 坐标空间1：原C0/C1/C2；拓扑1：project-14-v1；保留0 |
| 80 | u64 | 当前连接传输序号，从1连续递增 |
| 88 | 42个FP32 | 14×3坐标，关节优先、C0/C1/C2顺序，共168字节 |

现有CSI和显示IPC协议完全独立，不替换它们的包头或语义。浏览器接口以十进制字符串表示全部u64，避免JavaScript Number丢失身份精度。来源/发布/PC接收时钟属于不同域，不直接相减。

`Frame`拥有所有数值，无借用SDK地址；`encode/decode`检查字段。`TcpSender`仅接受数字IPv4，构造及单记录有2秒默认截止时间；完整发送后才返回，异常不重连或重发。调用方须在独立输出线程持有它；将来有界队列及对现有应用的接入不在本阶段完成范围。

`pose_replay records.piwpose IPv4 port interval_ms [fragment_bytes]`先完整验证至多10000条文件记录，再创建TCP连接。保留文件中的帧号和来源标记；`fragment_bytes`用于分包诊断，不改变记录。

固定14关节拓扑随协议版本管理。Node验收将其与当前项目渲染头文件对照；不得直接换为17关节、把候选槽号当作人物身份，或把归档重发解释为新推理。
