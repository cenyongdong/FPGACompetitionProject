## 获准的时间轴适配与输入频率复核：2026年10月20日

### 实施范围与数据流

新增独立主机工具`tools/vitals/adapt_octonet_timing.py`、`tools/vitals/validate_timing_adapter.py`。它们没有接入姿态、HDMI、Web、SDK、采集驱动或CMake产品目标，既有C++心率核及ARM64产物未改动。工具只使用现有NumPy／SciPy，没有安装、升级、访问板卡或新增数据集下载。

实际流程为：原始配对文件只读 → 在每个原始时间点计算同包双天线相位差并沿时间unwrap → 检查原始时间缺口与相位步进 → 线性插值到200Hz中间网格 → FIR抗混叠并转换到10／20／25／50Hz → 保存诊断相位及质量结果。原始相位门检失败时，插值后的平滑外观不能解除拒绝。真实相位数组没有伪装成双天线I/Q，没有进入`SyntheticUniform`或`VerifiedSampling`路径，也没有编造RF包序号。

200Hz仅为主机插值／滤波的中间网格，并非采集频率。采用`resample_poly`、Kaiser参数8.6完成低通与抽取；其滤波和边界语义按[SciPy官方说明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.resample_poly.html)核对。每边额外使用2秒真实记录，保留中间40秒，禁止源数据外推。200ms最大源间隔只是本次探索性拒绝上限，尚未证明可作为实际采集验收标准；FIR也不能补回缺失信息或校准RX相位。

### 真实记录的结果

子载波按两条RX均满足原幅度下限的索引排序，固定取10%、35%、60%、85%分位，得到数组索引12、39、68、96。该规则没有读取心率标签、寻找最佳频谱或依据误差调参。未核实这些数组索引对应的物理OFDM编号。

| FFT数组索引 | 全记录原始相位步进超过0.25rad的次数／3474间隔 |
|---|---:|
| 12 | 1329 |
| 39 | 1274 |
| 68 | 1301 |
| 96 | 1361 |

这些通道都存在接近π的相邻相位变化。为排除仅由四个索引选择造成的现象，又对全部108个幅度合格索引作只读诊断：每个索引均超限，次数1245–1842。此结果证明原相位不满足现有门限；**不能据此认定是人体运动、某一种硬件相位歧义或数据损坏，根因尚未定位**。未执行去尖峰、π翻转修正、RX校准或放宽阈值。

取相对原记录起点2秒、7秒开始的两个40秒历史，各试四种目标网格，合计8个诊断组合；它们高度重叠，不是8个独立样本。两组所需原始上下文的最大间隔均为143.162ms，满足本次探索性间隔上限，但全部因原始相位突跳未通过；RF时钟及源包序号证据也仍缺失。没有对真实记录运行心率判定，没有HR有效率、MAE或RMSE。原参考的95–123次／分和超出当前48–120次／分频带的16条记录保持，未删减、夹值或为了标签扩频。

[官方补充材料C.8](https://proceedings.neurips.cc/paper_files/paper/2025/file/14950adea25005f89545688fe97fe5ea-Supplemental-Datasets_and_Benchmarks_Track.pdf)说明其采集端为Intel AX200、每节点2条RX、114个CSI子载波，平均包率75.62/s。它与现有BCM4366／Nexmon历史三链输入不是同一采集链；论文平均包率不能代替本文件65.3421/s的实际时间戳统计，也不能保证两者相位性质相同。

### 已知频率信号验证与暴露的限制

验证输入全部为解析信号或可复现噪声，包括约9.615Hz均匀时间、约10Hz抖动时间、50Hz时间以及这条OctoNet的实际时间戳模式。每包加入独立随机公共相位，先差分抵消，再插值；只有这些完全合成的信号才为复用既有C++核编码成合成I/Q。数据集人体相位没有这样编码。

首轮26个用例中25个符合预期；针对10Hz漏检追加12个此前未跑的高心率／采样率组合，其中10个符合预期。没有为了消除失败重跑整套、改预期或调阈值。38个用例包含34个应检出心率的正例和4个纯呼吸／噪声负例；实际31个正例检出、3个正例返回空值，4个负例均返回空值。
