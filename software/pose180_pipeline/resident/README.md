## 实现与资源边界

```text
TX无线广播 → 三个RX → 各自有序PCAP/TCP → 板端CSI整理
                                            ↓ 最新完整窗口
                                      唯一SDK拥有线程
                                            ↓ 完整拥有值
                        HDMI同Device交接 ← 输出 → 可选PC订阅
                                            ↓
                                  非阻塞诊断环／独立记录进程
```

- [main.cpp](main.cpp)：复用原180-query epoch99、预处理和Runtime；唯一线程执行推理、同Device写帧及CSR。PC不再回ACK；本地HDMI在下一次可能变慢的推理前证明采纳，保留原200ms采纳及500ms tagged STOP所有权证明。模型、RAW、SDK、数学、AI四路及PIWCSI2／PIWFUL3帧格式未改。
- [core.hpp](core.hpp)：执行中1窗＋最新待处理1窗，各自拥有数据；默认500ms过期整窗丢弃。源帧、实际推理编号、接收代次和采纳计数独立。各消费者拿到自己的副本，不回收仍在使用的对象。
- [csi.cpp](csi.cpp)：三路按固定IP绑定；复用原NMD3、300Hz时间网格、20点同事件组窗和30载波映射。每RX最多2048事件、1600格、4秒历史；整理器待取窗口最多32个，PCAP增量缓存最多65,551字节。r5将组窗失锁与连接故障分开：失锁清空共同代次并保留TCP／解析器，仅传输故障RX重连，网络退避由RX统一负责；重新建立新鲜共同边界，旧在途结果不再发布。恢复诊断为16条×1024字节有界队列；实际软件验证与边界见[r5记录](STUTTER-VALIDATION.md)。
- [io.cpp](io.cpp)：结果发送仅有当前完整记录＋最新待发记录，慢客户端超过500ms断开；重连从完整记录开始。状态端口不访问设备。`39382`接PIWCSI2，`39383`输出PIWFUL3，`39384`返回一次JSON状态；启用`--csi`时停用PIWCSI2输入口，CSI使用`39033`。
- [journal.cpp](journal.cpp)：SDK初始化前fork独立记录进程。父进程8条PIWFUL3环约596KB；非阻塞SEQPACKET发送，满则丢弃并计数。四个分段，每段最多64条完整模型输入／180分数／180×14×3姿态和约256KiB文本，正常记录约20MiB上限。磁盘错误退避5秒，不阻塞推理；故障环冻结为独立文件，但IPC／磁盘失败时可能不完整，不能把提交请求写成持久化成功。常规原始RF CSI不全量落盘。
- [可选PC订阅端](../host/resident.mjs)：独立3D页面和可选Worker归档；记录仅1条执行中＋1条最新待写，四段×64条。没有板端控制、输入节拍或归档ACK依赖。

`--seconds 0`可让核心持续等待／处理输入；设备验证仍使用明确有限时长。下述r3实测使用16秒有限捕获与10秒TX任务。后续设备本地源端守护、独立启停和SDK原生日志上限已完成软件故障注入与[r4真实联合板测](LONG-VALIDATION.md)；本轮包含早期TX修复停顿，不能扩展为全天无人值守或无卡顿验收。

## 分级恢复

缺窗、过期、接收代次变更只丢弃受影响输入；PC掉线／慢客户端及记录故障只影响对应消费者。SDK调用慢时观察原调用，待处理输入保留最新；不并发另开Runtime，不因监控超时杀SDK。SDK明确失败、非有限值或非法候选进入`isolated`，保全原值、不发布、不自动重试，状态通道继续服务。HDMI仍必须按现有STOP／排空契约释放资源；共享总线异常不自动重启或假定仅显示失效。

状态包括`initializing/running/waiting_input/resynchronizing/degraded/isolated`，并报告输入／结果／采纳年龄、实际新推理、丢弃和重同步计数、最近接收故障原因。r5新增HDMI等待／重同步／过期和年龄提示，沿用唯一设备线程和原采纳／STOP证明；`display_updates/display_hints`与真实`inferred/adopted`分开，提示及旧画面扫描不计为新推理。r5已实际提交提示并验证恢复实屏，提示文案未逐条现场验收。
