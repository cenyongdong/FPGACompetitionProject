## 审查与修正

| 范围 | 结论／本轮处理 |
|---|---|
| 输入与调度 | `Latest` 在短锁内交接拥有值；CSI／数据集／TCP 互斥，旧代次及过期输入丢弃。最新手动启动器原先写死 CSI，现通过 `input_config.py` 共用显式选择与来源校验，运行请求保存选择，分离后的监督进程再次核对。官方输入缺失不会回退到实采。 |
| 参数健壮性 | `std::stoul/stod` 原先可能接受尾随字符、负号或转换后截断；新增完整数值解析，先检查时长／年龄／端口／次数上限，再换算和缩窄。CSI 配置同样核对完整值；监听端口重复在初始化前拒绝。 |
| 启动消费 | SDK 安全退出不代表启动消费 CSR 已重置。启动器现在根据本轮预约或旧原生日志，在同 boot 再启动前拒绝；只有确认未进入硬件阶段的失败才允许原有安全恢复路径。硬件中的原生一次性保护继续保留。 |
| 并发状态 | 状态线程取时间后，工作线程可能发布稍晚时间戳；旧 unsigned 相减可能得到极大年龄。现在对快照之后的时间戳显示年龄 0，避免误报超时。 |
| 日志完整性 | 状态 JSON 已超过旧 2 KiB 截断上限，截断还会与下一条记录连接。改为最多 8 KiB 整条发送，超限整条丢弃并计数；不阻塞推理或增加无界缓存。已有 streambuf 分片仍保留。 |
| SDK／HDMI 资源 | 核对唯一线程所有者、初始化回滚、输出首次读取、在途 ReleaseGuard、HDMI 标签采纳／STOP drain、未知 free 不重试、异常期间保留资源和独占。未改变 SDK、设备映射、模型图或硬件完成契约。 |
| 后处理与显示 | 核对原始候选／派生结果分离、Top1 无阈值、有限值与索引检查、确认及保持时限、单人连续性和 PC 丢旧／断线行为。仅消除像素范围比较的 signed/unsigned 警告，绘制结果通过原有检查。算法、视觉和数据协议保持。 |
| 可读性与目录 | 提取数值解析接口；按用户澄清收拢输入、预处理、SDK、后处理、显示、网络及诊断到 `src/`，将启停与数据准备移到 `control/`，相关头文件与实现同目录维护。同步 CMake、导入、PC 资源和打包路径；历史包／旧工程副本保留。 |

## 实际本地验证

- C++：后处理、单人连续性、绘制、显示状态、缓冲、日志、释放守卫、HDMI 分配／释放共 8 类检查通过；日志新增完整长 JSON、整条超限丢弃和并发时间戳边界检查。受影响目标增量重建并复验。
- 构建：Linux native/mock 与 ARM64 `pose180_demo` 通过；既有严格 `pose180_pipeline` 亦在首轮构建通过。最终常驻目标重新编译，使用既有 GCC 9.4／SDK 3.39，未构建 FPGA。
- Linux mock：Top1 无阈值、启动预检、双输入命令、数据集 EOF／3 轮身份、实时自适应输入、CSI 恢复、异常退出、生命周期、在途释放阻断、常驻故障共 10 项脚本完成验证。双输入命令实用 12 个官方 CSI 样本；数据集检查另用 24 样本及 3 轮重复。mock 不作板端新推理证明。
- 官方原始数据：290 个样本逐条校验记录身份、时间轴及抽取坐标的原 MAT 对应；未使用姿态标注作为输入。
- PC：13 项检查通过，包括分片／重连、无 ACK、过期隐藏、旧结果拒绝、有限值和性能统计。测试进程预算由 10 秒调整为 20 秒，以容纳其主动 5.2 秒等待、重连和 Windows 资源读取，原行为断言保持。

首次检查原值保存在构建工作区：构建容器无 Python、默认 Python 无 h5py 均通过使用已有环境解决；新双输入测试夹具的输出父目录错误已修正。Windows bind mount 上异步日志发生丢弃／部分落盘，因此需要完整日志的复核在容器 `/tmp` 执行后再复制结果。CSI 恢复检查还直接暴露并验证了上述 2 KiB 状态截断修复。一次本地强杀 mock 后端口检查失败、一次 FD 计数 4→5 未在独立复验中重现；对应最终检查通过，完整启停三轮 FD 为 4→4。保留这些原值，不把单次复验包装成长期无泄漏证明。
