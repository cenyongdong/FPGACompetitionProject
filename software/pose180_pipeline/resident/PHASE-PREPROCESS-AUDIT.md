# 姿态预处理的相位跳变诊断

2026-10-27。用户要求检查现有预处理能否消除相位跳变，并提出解决方法。本轮只读源码、离线复用两段已有录制并运行纯数学检查器；**没有现场采集、心率功能恢复、模型推理、SDK／设备访问或正式预处理修改**。

## 结论与当前代码

当前预处理能显著减小公共相位偏移及线性相位误差，但**不能消除全部时间跳变，并且独立的相位分支选择可引入额外跳变**。这与跨路由器时间戳重匹配是两类问题，包对齐不能自动解决 CSI 复数相位的异常。

常驻程序实际由 `software/pose180_pipeline/CMakeLists.txt` 链接 [demo_v1/shared_fp16/preprocess.cpp](../../../demo_v1/shared_fp16/preprocess.cpp)，其本轮摘要与 [software/core/input/preprocess.cpp](../../core/input/preprocess.cpp) 相同；原始方法对应官方仓库 `WifiPoseDataset.CSI_sanitization`。

实际步骤为：

1. 每个 RX、每个时间点独立计算，首天线的 30 个载波相位沿**子载波轴** unwrap。
2. 利用同包相邻天线的共轭乘积相位依次展开其余两根天线，再沿子载波 unwrap。
3. 对三天线的 90 个相位点联合拟合、去除公共线性斜率与截距。
4. 重建复数并取 `arg`，相位重新回到 ±π；与幅度拼成原 `[1,180,60]` 输入。

这里没有跨时间的相位状态、突变检测或逐包分支跟踪。幅度的 db11 小波对 20 点窗口分解层数为 0，也不是时间相位滤波。原论文采用线性变换做相位去噪，并不构成针对任意时间跳变的保证。[原论文第 3 节](https://aiotgroup.github.io/Person-in-WiFi-3D/paper/2024CVPR_Person_in_WiFi_3D.pdf)

## 已复现的额外跳变

复用现有 `software/pose_v1/src/preprocess_check.cpp`，直接编译当前正式 C++ 预处理；三个合成诊断均与原训练方法对照，圆周相位差最大约 `1.14e-7 rad`。以下是合成输入，不是人体实测或模型精度结果。

| 输入变化 | 当前 C++ 校正后的最大圆周变化 | 含义 |
|---|---:|---|
| 三天线共同跳变 1.2 rad | 约 `1.4e-15 rad` | 能消除这类理想公共相位偏移 |
| 仅第三天线跳变 1.2 rad | 约 0.8 rad | 天线间差异并没有被共同斜率／截距消除 |
| 天线间相位差平滑跨 π，原始最大变化仅 0.01 rad | **约 2.101 rad** | 独立选分支可把很小变化放大成特征突跳 |

第三例的原因不只是最终 ±π 表示换行：按各时刻分别展开时，后两根天线的分支可同时改变 −2π，第一根保持原分支。公共截距随之改变约 −4π/3，校正后会出现约 **2π/3（120°）** 的共同旋转，原始天线间变化其实很小。本例的 2.10 rad 用**圆周差**计算仍存在，不能把它当成单纯的 `+π → −π` 绘图换行。

这属于原训练方法也存在的分支问题，不是已证明的 C++ 部署独有错误；也不同于历史浮点 atan2 在人工 ±π 边界的跨语言差异。原训练等价性和历史数值结论保持。

## 离线候选与已有实采结果

诊断候选先沿时间保持同包天线间相位差的分支连续，再做原来的跨载波展开、公共线性拟合和最终相位映射。它只改变 2π 整数分支的选择，**没有低通平滑、扣除拟合的射频跳变、改变幅度或抹平圆周天线相位差**。只处理单个已知连续采集段；本轮另在源间隔超过 10 ms 时重置分支，避免盲目跨缺口延续。10 ms 是离线诊断配置，不是新的生产验收门。

在上面的平滑跨 π 合成例中，该候选的最大变化为 **0.00667 rad**；单天线 1.2 rad 的真实输入阶跃仍留下约 0.8 rad，没有靠强制平滑消失。

复用 `.local/vitals-hybrid-20261026/real-rx1-r1.pcap` 和 `real-rx1-r3.pcap`。这里只使用已有 CSI 做姿态相位诊断，不调用心率分析；r2 因摆位发生变化，不混入本次比较。按原 30 载波位置恢复 NMD3 保存的原始 FFT 字，保持原 first-valid 去重与连续段划分。

统计“天线 0 中至少 15／30 个载波的相邻圆周变化超过 0.25 rad”的次数：

| 已有录制 | 事件／实际相对 RX 时长 | 当前方法 | 时间分支连续性候选 |
|---|---|---:|---:|
| r1 | 17,936／59.995824 s | 544 | 13 |
| r3 | 17,926／59.996100 s | 1,099 | 580 |

0.25 rad／15 载波仅是统一的描述统计阈值，**不等于判定这些变化都是硬件故障**。统计针对一根指定天线，没有把三天线的同一事件重复相加当成独立故障。r3 有三处超过 10 ms 的缺口，最大 31.148 ms，候选在这些位置重置。

三对天线的圆周差宽带跳变计数在当前方法和候选中均保持：r1 为 37／14／35，r3 为 1151／574／2390。它们不能被统一的线性斜率／截距消除，亦未被候选抹平。当前／候选对原始圆周天线差的最大误差分别在约 `6e-15`／`1.6e-14 rad` 以内。

因此，**部分突跳确实可以通过分支连续性修正减少，但较差录制中的天线间突变仍很多**。单根接收链的状态变化、非线性误差、衰落或真实动作都仍可能参与，不能由这些录制唯一确认 AGC、PLL 或某台路由器故障。802.11ac 文献报告过接收链的离散相位状态，但实验对象是 Intel 9260，不能直接给本项目 BCM4366 套固定 π 补偿。[原研究](https://arxiv.org/abs/2005.03755)、[无线感知校准教程](https://tns.thss.tsinghua.edu.cn/wst/docs/sanitization/)

## 建议的实施顺序

1. **先做可关闭的时间分支连续性候选。** 原严格预处理函数继续保留。状态按物理 RX 的原始完整事件推进，避免重叠／重放窗口重复推进；身份、时钟段变化或长缺口重置。优先验证上述已复现的额外 120° 跳变，不额外加入大延迟低通。
2. **用圆周量检测余下异常，保留局部恢复。** 同时检查多载波一致性、三对天线差、幅度及源连续性。单个异常事件可由容错组窗跳过、用后续真实事件补足 20 点，不回到数秒停供。仅凭“变化大”不能区分人体运动与接收状态，不能把所有相位变化统一扣掉。
3. **对剩余接收链偏移另建有证据的状态模型。** 只有明确观察到稳定、可复现的离散偏移时才考虑有置信度和滞回的状态补偿；模糊情况保留原值及质量标记。本轮未恢复现场标定或驱动修改。
4. **启用前做模型效果对照。** 候选仍输出相同形状，但相位取值会改变；必须在同一官方样本和已有三 RX 数据上比较原模型的人数、置信度、坐标、轨迹突跳及有真值时的误差。当前两段单 RX 信号统计不是姿态精度证明。最终 ±π 标量换行仍可能存在；改用 sin／cos 等编码会涉及训练特征和模型，不能直接替换给原权重。

本轮没有把候选接入正式服务，也没有改动模型、SDK、数学基线或输出 UI。全部代码与数值证据保留在 `.local/pose-phase-audit-20261027-r1/`：`audit.py`、`analysis.json`、三份合成输入／实际 C++ 输出及纯数学检查器；`analysis-without-gap-reset.json` 保留候选早期未分段诊断值。信号跳变减少与推理画面改善仍分别认定。
