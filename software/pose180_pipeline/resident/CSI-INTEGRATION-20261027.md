## 修订：隔离可信 PCAP 边界内的坏网络帧

非计划缺口由网络帧解析错误触发，并非后台拟合主动停供。针对这一局部问题，[PcapStream](../../../tools/nexmon/board/pcap_stream.hpp)新增显式 streaming 隔离选项，仅在自适应实时入口开启：

1. 全局头、记录头、捕获长度和完整记录边界仍须通过原检查。边界不明、长度不可信、时间回退等继续报错并恢复连接，不扫描猜测下一个边界。
2. 已取得完整可信 PCAP 记录后，其中 Ethernet／IPv4／UDP 的格式错误或不支持帧可单条丢弃；不解析成 CSI，也不改写字节或填补样本。
3. 保存累计计数、最后一条错误原因、记录序号、原始时间戳及最多 64 字节网络帧头部片段，写入有界诊断。若一次 append 内有多条错误，记录增量计数和最后一条片段；不是完整坏包归档。
4. 只有完整、通过原 CSI／NMD 身份及连续性检查的事件进入组窗；缺失 CSI 片段由既有局部解码恢复处理，继续用后续真实样本。

原严格解析默认不变。Linux 的 **218 项 PCAP 检查、29 组原 Ingress、8 组自适应算法**通过；坏 IPv4 帧的同一 TCP 流中，前后有效记录均保留，分块边界检查通过，PCAP 时钟／边界错误仍拒绝。真实 Csi 适配器 TCP＋mock 注入同类坏帧、无效样本及计数故障：103 次 mock 推理、坏帧计数 1、局部解码恢复 2、全局重同步／传输重建 0，最长结果间隔约 131 ms。该项是软件注入，非射频实采或 SDK 精度结果。
