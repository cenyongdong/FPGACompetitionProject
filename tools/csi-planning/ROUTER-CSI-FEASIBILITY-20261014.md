# 路由器替代采集节点：可行性与模型影响

日期：2026-10-14。用户补充：为采集购买x86主机不经济，近期希望现场实时采集，询问路由器替代及精度影响。本记录补充同目录CSI-ACQUISITION-REVIEW-20261014.md，不将上一轮以复用5300为优先的推荐固化为采购决策。

## 结论与范围

支持特定CSI提取工具的路由器可以同时承担嵌入式采集宿主和无线接收器，避免为每个接收点购买x86主机。普通原厂路由器或仅能安装普通OpenWrt的型号不因此具备CSI提取能力。预算优先时，建议先借用/取得一发一收Atheros路由器样机核验，再判断是否值得扩展三收；接受的是输入适配与新数据精度验证成本，不是已经证明可无损复用固定5300权重。

本轮只在Windows PowerShell、D:/FPGACompetitionProject阅读固定预处理与前一分析、浏览原始工具文档及设备资料。没有安装、下载刷机镜像、刷写路由器、无线采集、修改代码/模型/SDK/BOOT、访问Lite或恢复暂停的DATA排查。实际产物仅本分析记录；通过项仅文献与代码契约核对，设备实测和性能均未知，无新增后台工作。

## 已查到的具体路线

### Atheros / 修改版OpenWrt

[Atheros CSI Tool原始项目](https://wands.hk/external/wifi/AtherosCSI/index.html)提供Ubuntu及OpenWrt版本，作者验证芯片包括AR9580、AR9590、AR9344、QCA9558。其CSI在20MHz常为Ntx×Nrx×56，40MHz为Ntx×Nrx×114，并带包载荷、时间、RSSI及速率等信息。硬件、驱动和配置决定具体维度，不能把所有ath9k型号直接视为已实测。

具体低成本样机候选为TP-Link TL-WDR4300 v1（须核对具体硬件版本）：[OpenWrt硬件表](https://openwrt.org/toh/hwdata/tp-link/tp-link_tl-wdr4300)明确5GHz AR9580 / 3×3，2.4GHz为2×2，8MB Flash / 128MB RAM。因此应选5GHz部分验证三接收链。开发者[CSI客户端项目](https://github.com/putterer/csi-client-app)明确记载实际用过WDR4300及WR2543ND采集，路由器需要修改版内核及CSI工具；这个记录不能代替本项目样机验收。WDR4310 v1亦有[相近硬件公开资料](https://openwrt.org/toh/tp-link/tl-wdr4310_v1)，具体板型/镜像/CSI支持仍需分别核对。

WDR4300是停产旧设备，[OpenWrt设备页](https://openwrt.org/toh/tp-link/tl-wdr4300_v1)指出其资源不足，不推荐未来通用OpenWrt使用。此处将它列为历史CSI采集实验的样机候选，不推荐购买多台或用作长期联网主路由。当前OpenWrt支持某设备不证明历史CSI补丁可直接用于当前内核；必须绑定具体可编译/可恢复的CSI镜像、驱动及板型。本轮没有核实二手价格、库存或可工作的预编译套装。

### Broadcom / Nexmon

[Nexmon CSI原始项目](https://github.com/seemoo-lab/nexmon_csi)明确支持ASUS RT-AC86U上的bcm4366c0（指定固件10_10_122_20），提供编译/安装步骤及UDP输出。按无线接收核和空间流配置，每帧可产生多个CSI UDP记录；带原发射MAC、无线帧序号、核/流标识和信道参数。20/40/80MHz分别输出64/128/256个复数位置，包含的有效位置须按配置识别。该路线支持研究多接收链，但本项目所需三链的同时输出、连续采集率和丢记录情况尚未实测。

这是另一条无需新增x86采集节点的路线，固件版本和无线芯片绑定更紧；不依据型号相近推定其他ASUS路由器兼容，也未证明其当前二手成本更低。

### 只用路由器发射，保留5300接收

[PicoScenes采集文档](https://ps.zpj.io/manual/scenarios.html)存在5300从关联802.11n AP提取CSI的模式，且可控注入帧另有配置要求。它能减少独立发射主机需求，但仍需三组5300接收硬件及宿主，并不解决全部x86节点成本。发射率、单流、加密、帧格式和三收共同包身份须核验；普通路由器网络流量不自动满足论文采样配置。

## 输入变化与精度

固定输入仍为3接收点×3接收天线×30点×20时刻。保持三个分布式接收点，不能用一台三天线路由器直接替代三个接收点。路由器收原始CSI、经网线给蛟龙笔记本解析/对齐/适配，再以既有PIWCSI1向Lite送完整窗口是可研究的分工；路由器无需运行姿态Transformer。

现有[preprocess.cpp](../../software/core/input/preprocess.cpp)实际将abs(csi)作为幅度特征，无跨设备自动标定；相位处理联合三条链，并使用固定step=2π×625.0及30位置索引。它不是任意网卡数据的通用适配层。

| 差别 | 当前权重的风险与处理边界 |
| --- | --- |
| 子载波表示 | Atheros56/114、Nexmon64/128/256与5300的30点不同。应核对物理子载波索引、信道和带宽后设计复数选择/插值；不能随意取前30点，插值也不证明采集统计等效 |
| 幅度量化/尺度/增益 | 工具原文指出Atheros与5300量化不同，AGC及尺度还需按实际记录核对；扩大输入dtype不能恢复或统一测量尺度 |
| 相位/天线链/几何 | 不同射频链、链排列、馈线和天线位置会改变测量；现有线性校正不能自动保证消除跨硬件差异 |
| 时间与三收对齐 | 仍需近论文采样密度、连续20时刻及共同包身份；广播、多站关联或轮流ping的具体行为须测试，不能拿不同包的三路记录拼成同一时刻 |
| 场景变化 | 同型号5300也有房间、家具、人员及空间布局变化带来的输入差异；换路由器新增设备差异，不代表所有误差都来自硬件 |

技术判断：直接把路由器CSI转成相同数组形状后输入原5300权重，应按明显退化风险规划，尚不能给出退化百分比，也不能宣称必然失败。更多子载波并非天然更差；若测量稳定、适配正确，并在匹配的路由器数据上训练/微调，模型可以研究重新适应，但少量微调是否足够、能达到多少精度均须验证。

## 建议的决策门槛（未实施）

1. 先一发一收样机，验证实际Ntx=1、Nrx=3、5GHz CSI完整输出；保存原始CSI、包身份、配置、时间、RSSI/增益可用字段及有效接收率。成本报价包含可工作软件与恢复方式，不能只有能刷OpenWrt的承诺。
2. 扩展三收前核验统一发射包的采集方式；扩展后统计共同包和连续窗口成功率，不只统计单节点300Hz。
3. 设计独立输入适配层，保留原始完整路由器CSI；原固定5300预处理/回放基线不覆盖。选择/插值、幅度标定及相位处理都要记录假设。
4. 对有同步3D标签的新数据先评测固定旧权重。再视结果讨论微调/重新训练及部署变更，按采集会话或场景独立留出验证数据，避免相邻帧泄漏。单看骨架画面动起来不等于姿态精度通过。

如能借到5300采集链，建议同场对照帮助区分硬件差异；借不到也可用路由器CSI与3D标签评测绝对性能，但不足以单独归因设备变化。样机预算、测试时长、场地、可用路由器及标签设备均未确定，不擅自启动采购或实验。

推荐随优先级改变：若短期要求最大限度复用原权重，5300节点仍有优势；若预算优先且能接受新输入适配和精度验证，Atheros路由器样机是值得先核验的候选。总成本包括硬件、驱动/刷机、同步、标签和训练工作，当前没有实际报价与性能测量证明哪条最终最经济。
