# 当前 SD 卡/读卡器全容量检测方案（待批准）

## 依据和目的

当前启动卡 BOOT.bin 与用户此前已替换的指定 Lite 参考 BOOT.bin 不一致，卡当前启动头为零；内核/设备树/uEnv 等也异常。此前写后校验失败两次，最新写入跳过校验。用户现已更换绿联USB3.0读卡器（实际USB序列号000000000819）并重新制作，确认未校验、未替换参考BOOT；冷重连后8/9文件仍不匹配。需要验证现有卡与新读卡器组合能否完整、可靠存取，再讨论重新制作系统。

## 具体操作（未执行）

1. 将当前可读 FAT 根目录文件备份到项目诊断目录，保留摘要及异常证据。此备份不是整卡或 Linux 分区备份。
2. 从 H2testw 官方发布页取得便携工具。每次破坏性操作前重新核对 USB 读卡器序列号 000000000819、约67,101,834,240字节容量及实际磁盘号；不能只依赖原 Disk3 或 E/F 盘符。身份变化或不唯一时停止。
3. 删除该 SD 卡现有分区并建立单个覆盖可用容量的 Windows 可写分区（采用 exFAT）；现有 FAT 启动分区与 Linux 分区全部清除。
4. 用 H2testw 测试全部可用空间，进行写入和读回验证，保存原始结果、完成范围、错误量、速度、工具版本。只测试当前 E: 的1GiB不能作为64GB容量验收。
5. 检测结束后报告。失败只能证明当前卡/读卡器组合不可靠，不能仅凭一次测试失败单独认定假容量或卡损坏，需结合错误分布/可保留数据范围及必要的另一张卡对照。通过仅证明本次测试，不能替代后续镜像写后校验和实板启动。

## 影响与边界

本方案会清空整张目标 SD 卡。不会改写电脑系统磁盘、板端Flash/BOOT、FPGA配置或永久工具配置；不包含系统镜像重写和BOOT替换，重制步骤在结果出来后另行讨论。工具下载及破坏性检测均待用户对本方案明确批准，尚未实施。
