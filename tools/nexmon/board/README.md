# 路由器直接进入开发板：软件候选

2026-10-25。按用户要求，正式采集／推理链不经过PC。**本目录的C++候选、Linux网络回放与ARM64交叉编译已完成；开发板当前不可用，未部署或运行实机SDK。** 当前只支持一次明确的≤3000事件TX任务，不是已验收的常驻系统。

## 运行链与接线

```text
专用TX ──同一无线广播──→ RX1／RX2／RX3
                            │ 三条有序PCAP TCP流
                            ▼
开发板PS：配对／三链组装／同帧对齐／300Hz组窗／30载波与固定尺度
                            ▼
原CSI预处理 → 原180-query模型SDK调用 → 板端完整原值与姿态结果
```

第二台TX的LAN1接开发板，LAN2/3/4接三个RX，WAN全部留空，共4根网线。路由器LAN交换能力已够用，无需另买交换机；交换机不提供三台无线芯片共享TSF。开发时可用第5根线把PC接任一RX空闲LAN，仅作SSH诊断。四机身份及已批准地址统一见[四机实测](../evidence/multirx-20261025-r1/REPORT.md)。

开发板采集地址暂拟`192.168.50.49/24`，保留原`192.168.126.49`；**尚未实际添加**。三台RX直接连接板端39033，每机一个独立有序连接，原CSI/5500和NMD3/5501以原PCAP记录顺序传输。不存在PC代理、PC文件发送器或PC结果ACK依赖；本候选将完整输入／输出保存在板端新目录，HDMI和网络展示尚未接入。

原模型／RAW不复制或改写。原`demo_v1/shared_fp16/preprocess.cpp/.hpp`按原文件直接编译链接，源身份与冻结清单一致。仍按外部`[R3,A3,T20,N30]`／complex128生成原PIWCSI2/v2记录，原解码器交换T/N后调用同一预处理，输出FP32`[1,180,60]`。没有改SDK、Host计算注册、NPU分配、既有外部帧协议、BOOT或启动脚本。

会话和接收器身份由本次有界采集控制流程提供，NMD3自身不含应用batch/slot编号。源MAC／信道／序列空间／完整SeqCtl／帧长一致且无歧义才能关联；不使用网络到达顺序或系统墙钟作为共同采样时刻。保留原1秒启动、至少120事件、集中度0.75、300Hz固定周期、±833.333µs点位门槛；共同anchor只固定整数slot偏移。三台每格必须是同一真实事件，每20格一窗，缺测／超差整窗丢弃，不插值、不补帧、不事后拟合相位或漂移。

帧号和来源时间仍使用原字段；本机单调时间只表示整理器的发布时间，不冒充绝对RF到推理延迟。三台独立射频时钟没有因此变成同钟或相干。出现会话／时钟／序号歧义就终止当前批次，不能把新任务接到旧缓存。当前最多缓存一个有界任务；`take_ready()`在数据结束前增量输出，不等全部10秒结束才输出。

三节点增益必须显式指定且有限、为正；示例配置保留空值，测试的1/2/3仅用于检验布局与尺度运算，不能用于人体精度结论或直接抄为现场配置。旧单节点经验系数没有直接套用。队列满时只丢弃尚未交给SDK的整窗并记录，不覆盖队列，不复用旧窗伪造新推理。
