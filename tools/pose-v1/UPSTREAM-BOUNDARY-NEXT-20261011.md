# 下一阶段：首次read／Host暂存边界定位

日期：2026-10-11。仅准备接续方案，本文件不代表新板测或根因修复。本批完成点见[结果](UPSTREAM-BOUNDARY-RESULTS-20261011.md)。

## 实测依据

唯一QPC5.05诊断55正确后192初始索引1584变化／1582非整数，而两轮晚源逐位正确，数据输入正确。旧582晚源仍坏及其他192坏块证据保留。当前最应区分的是源生产时刻、公开read返回时刻、目标Host字节首次形成及CPU使用前的边界；不要据晚源正确直接认定copy或cache责任。

## 接续顺序

1. 本机先审查与板端身份匹配的Tensor::read、waitForReady、设备memory读实现、DMA完成及Host目标所有权接口。只使用已有源码／明文头／发布资料；缺失内部实现就明确记录证据限制，不把计数234当fence，不猜延时／cache／对齐。
2. 设计新的独立输入读取观察模块。仅对192索引，在公开read前后记录时间及源／目标身份，read返回后立即保存拥有字节，CPU调用前再次观察同一目标字节；异常仍保留原Host和两轮晚read。源与目标、读取完成与数学使用阶段分开。不修改计算／索引拒绝／频率或SDK；验证观察操作本身的线程归属、目标生命周期及字节所有权。
3. 根据实际SDK契约判断是否存在可用的完成通知或读事务同步接口。若没有公开证据，不用任意sleep／cache helper充当同步，也不在本批接入零拷贝。紧邻独立第二次read如采用，仅为时间边界取证，不自动用它替换坏值继续推理。
4. 新身份Native／ARM契约→Host107→四窗口完整数值／来源回归；每次产物审查通过后才考虑一次同样固定QPC5.05／103有界诊断。保持硬件180秒、原745／reset(1)、异常完整保存后停止。新目录保留本批及旧失败，不重跑停止的Engine，不调整频率凑通过。

保留原Gather和ZG边界观察。若后续需要Value1860量化支路，必须按实际FP16存储、量化元数据、原始字节及身份设计独立适配，不将其直接当普通FP32。当前失败未到Gather，先不扩大成新内核或计算图修正。
