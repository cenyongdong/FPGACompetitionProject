# 有限输出异常的单帧取证与独立落盘接入契约

本批已完成SDK无关`invocation_evidence`模块与Native/ARM自检，尚未将它接入冻结stage-guard-r1，也未执行新NPU候选。[ADR_20](../../ADR/ADR_20.md)及[失败报告](STARTUP-GUARD-RESULTS-20261009.md)为依据。

1. 新隔离版本为Host快照模块增加可选SDK无关observer：传出frame/invocation/op/slot和已拥有的字节。从**现有复制后shadow**复制或共享不可变拥有字节，不再次读取原Host指针冒充相同时点；默认observer空，旧接口和Host107初始化不改变。不要包含其他.cpp或读取其私有状态。
2. 主线程持有Frame对象，通过明确回调记录每帧五类适配算子的8输入、115360字节，直到完整结果比较结束。单帧≤1MiB、输入≤8，下一inv清空；线程或身份不一致拒绝，不能无限保存每帧原始值。真实参数、源/目标布局与地址元数据沿原记录和模型身份关联。
3. 最终有限输出或参考比较失败时，先保存完整实际结果及当前Host帧，保持原异常和停止规则。CPU异常继续沿旧暂存＋两轮源读回。首次集成不增加正常设备读回、不改原SDK复制、582计数等待、CPU数学/reset(1)/745和Gather/NPU分工。
4. 各项持久化分别通过flush执行：结果（可重抛原比较）、元数据、Engine证据、失败Host帧、warmup、稀疏ARM诊断画面。结果比较再抛错不应阻断后续任务。保留原计算异常并记录每任务成功/失败，画面重建不代表数值正确。不能回填本批已丢失元数据。
5. 先新构建与SDK-free接口/异常所有权测试；Host107保持，并用实际Host张量模拟“CPU前向完成后，最终结果比较拒绝”，确认一帧字节、元数据及ledger可读，旧CPU异常两轮读回保持。通过后新三窗完整门检，再单次有界103；异常完整回传后停止，不执行旧第二次或第三次重试。

若CPU输入shadow与同CSI旧中间参考不同，再按来源/复制时间/晚读追踪；若全部Host输入一致而最终输出不一致，再准备Engine内的公开、拥有且有明确生命周期的输出读取证据。后者须确认会话完成后的实际输出对象，不跨模块访问私有Tensor、不误把生命周期后复用内存当原输入。新SDK输出读回、指针映射与cache策略另设具体内存契约门检。

更长计量和零拷贝继续后置。当前有界模式的2048元数据、103请求和1000编码帧上限不能直接当30分钟服务；HDMI配套仍未确认。不以最高分骨架不变而降低完整100候选门禁。

同步边界的后续核查不只看582：静态生产结束223/234/477/481/638/720对应六个Host节点，当前只有638额外新查。所有组已核验无当前Host祖先依赖，但全组完成仍不是DMA fence。先保存当前帧输入，必要时用SDK公开回调观察其他读取时刻的实际计数，再选择最小等待修正；不覆盖原Gather注册、不擅自改ready_或采用私有寄存器/指针映射。见[SDK审计](SDK-MAPPING-AUDIT-20261009.md)。
