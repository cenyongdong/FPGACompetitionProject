# 设备源与Host暂存差异后的最小取证准备

103门检按异常规则停止，未自动重跑。失败S13_07_304/inv60/ScatterND582输入0有4个0xffffffff NaN；两轮PL DDR源读回均有限、相同且逐位旧同CSI中间参考，输入1暂存也正确。输入0有2096个值改变，主要为256字节周期中的128字节区间。当前证据首次区分了异常Host暂存与**稍后**正确源数据，尚不能区分原读取时间、SDK临时缓冲、Host目标可见性或后续写入。

本轮已经完成匹配插件d55e4887…5fc7178及XRT a29e4eee…749dc96的本机函数范围审计。跨区域默认memcpy分配并清零临时字节，调用源read、目标write，再释放；PL DDR read经dmaRead和尾部处理。Tensor::read与默认copyFrom共享PL DDR读取入口，但目标缓冲和调用时刻不同。不能仅凭晚读正确就认定更换API已修复，也不能把同区域PL DDR dmaMemcpy入口误归入Host路径。

下一最小候选准备方向：

1. **保存原复制返回时的Host拥有字节。** 保持原等待和copyFrom，在每个当前CPU输入复制返回后，把Host CPTR数据复制到有界、拥有的shadow（目标仅本轮六类Host输入，单调用≤1MiB）。不读设备源、不增SDK查询，不写盘。正常数学仍使用原Tensor；异常时将shadow、CPU拒绝后的暂存、两轮晚读同时保存，继续原错误。数据有限性/索引拒绝保持，shadow不是“修复值”。
2. **补全目标元数据与时间。** 记录原复制开始/结束、shadow完成、CPU错误的steady_clock，Host区域类型/chunk身份/CPTR数值及模64/128/256的对齐、原声明及容量。只读公共字段，不解引用ADDR/BOTH。以shadow是否已经错误，区分“返回时就异常”与“返回后变化”；时序观测不等同因果证明。shadow会增加CPU读取和改变缓存/时间分布，须单列诊断开销，不把新候选未复现或新增读本身作为修复/性能通过。
3. **完善输入失败清理计数。** 当前失败未到TimedWindowInput.finish，所以没有receiver终止计数；发送成功62条没有板端ACK，不能写成收到62条。新适配层应在正常/异常都保存公开Receiver统计与当前已拥有窗口身份，原Receiver/单槽/协议保持，不猜测或补填历史。
4. 新独立身份先Host107及shadow所有权/异常传播/地址边界，再原三窗完整数值和视频。只有门检通过且进入下一议定的有界诊断后才运行新硬件；旧103失败不重跑，不循环制造失败。

可审阅的后续选项：直接SDK read到已有Host CPTR以去掉跨区临时/write步骤，或不同对齐的SDK Host目标缓冲独立往返验证；这些属于新的正常搬运适配，须先核对实际函数签名/区域契约与测试数据，再讨论最小验证。不先改驱动、cache/屏障、SDK、CMA/BOOT，不静默替换NaN、加入sleep或重置帧协议。

本文件仅为失败后的本机分析与下一取证设计，未实现shadow、API替换或新设备测试。保留原r1/r3坏块及r2完整源数据；103/100计量、严格5Hz、HDMI/30分钟仍未通过。当前资源与连接已释放。[结果](BOUNDED-LOAD-RESULTS-20261009.md)／[检查点](evidence/bounded-load-20261009-r2/next-checkpoint.json)。
