# 实际推理画面接入编码的准备（2026-10-07）

用户已审查动态骨架视频并要求继续推进；沿用NEXT-VIDEO-PLAN中的F0-A授权。独立RTSP传输/保活/加入/重连及直接FFmpeg解码已实测，仍为预生成码流，不视为实际推理→VPU→RTSP闭环。本文件确定接续边界，不表示下列板测已执行。

## 已核对的接入点

- `application_core.hpp`：一个Engine串行`process_window`，返回原始100分数、4200坐标、帧号/时间、状态和单时钟计量。原SDK/数学/注册/复制、Gather/Matmul和reset(1)/最终745保持。
- `skeleton_render.hpp`：`draw`只做显示投影；生产仅生成NV12，先不同时生成三种诊断格式。转换仍为已核验BT.601有限矩阵，不改模型坐标。
- `vpu_encoder.hpp`：当前是2..60帧文件接口。新增隔离的有界生产者/packet入口，保留r5冻结源；所有输入在CPU复制完成后才QBUF，所有capture在复制为owned字节后才归还驱动。保持QUERYBUF opaque cookie。
- `rtsp_replay_check.cpp`：已证明live5552024.11.28、实际SPS/PPS、离散NAL、IDR加入和90kHz时基路径。当前54帧索引合同只支持单slice，不能包装成通用AU解析器或在线VPU服务。

## 接续门检

1. **接口和纯Host门检**：定义拥有NV12、源frame_id、invocation、encoded_id、生成时间的帧对象；画面队列最多2，单Engine保持。捕获packet拥有字节、PTS和flags；队列上限、错误/停止、重复帧政策显式实现。停止时先停生产并等待队列归还，再释放资源，不能保留已交回VPU的指针。
2. **F0-A1有限串行合并**：先原308/309/310/重复308，完整分数/坐标/PS输入逐位此前参考；真实输出画面→NV12→同进程VPU。仅8至12个编码帧、每幅新结果可明确重复，最多180秒。保存所有源映射与输入/输出内容、复制/所有权/层数和内核记录；输出与同轮Host画面匹配，不拿旧预生成数据替代。该步证明接入与资源兼容，不宣称实时吞吐。
3. **F0-A2有界实时分支**：一个推理工作者与一个画面/编码工作者；网络完整窗口单槽保持，画面队列最多2。编码名义10fps可以重复最新已完成骨架，明确记录“新结果”和“重复”，PTS依据真实采样时钟，不能用较短名义PTS掩盖推理延迟。先27窗口2Hz回放，保存源frame_id、queue/丢弃和实际争用；首版不做零拷贝或新CPU数学。
4. **F0-A3 RTSP接入**：保持live555事件循环单线程；有界owned AU桥与生产线程通知须先核对现有API的线程约定。使用实际参数集和IDR边界，慢客户端不能随意丢P帧；发生超限停止或有依据地从IDR重新开始。有限三帧/27帧联调、主机逐帧映射、加入/重连与结束，再计量整机。

每一步新包/构建/目录，核验当前阶段后才下一步。工程失败完整保留，不自动重试/复位、换SDK/模型/BOOT或退回全CPU。身份变化、OOM、总线/SDK/VPU异常、不同输入全部输出相同、非有限或来源错配即停。

## 色彩和HDMI尚缺项

FFmpeg trace_headers已经明确当前SPS有timing_info，但video_signal_type_present_flag=0，未显式声明矩阵/色彩。RTSP200帧和直接播放器100帧均与原视频像素一致，这不替代跨播放器色彩标定。先核对现有MVX控制能否输出已确认BT.601有限信号；如只能改SPS元数据，另建副本并记录仅元数据/VCL不变的对照，不猜测未确认的primaries/transfer。

HDMI目标1080p60不变。当前BOOT时序/clock/scanout归属和停止协议仍缺证，本轮不写参考地址、不更换BOOT。HDMI支路暂不加入合并程序；先完成实际推理→编码→RTSP，后续有配套证据再实屏。

整机5Hz、P95、10Hz姿态更新、双路及30分钟仍待专门验收。离散回放10fps、核心5.25Hz或此次RTSP100帧均不能替代这些指标。
