## 设计与物理结果

AI HC0→HP0、HC1→HP1、HC2→HP2 S00、HC3→HP3，以及 HDMI→HP2 S01 保持。消费器默认 WAIT；新增 0x400b0800 诊断接口允许软件仅一次开启消费，保持最多 256 拍、4096 个 HP 周期、64 个空闲周期的边界。CHKR 仅重新武装被动协议检查器，不复位业务接口。BRAM bank0 保存首次 PS RVALID，bank1 保存消费首次 RUN；两个原始窗口各自保留。

完整布线签核：setup WNS +0.030 ns、TNS 0；hold WHS +0.012 ns、THS 0；113081 条可布网络全部完成，内部未约束端点 0。新增控制握手、回复与命令端点逐一通过有效的 5/10/5 ns 约束检查，必要 DRC、总线偏斜及现有诊断边界检查通过。仍有原已批准的两项 AI 最小周期例外（−0.409/−0.071 ns），因此 raw_timing_pass=false；没有新增时序例外、频率修改或 DRC 豁免。

## 实际板测现象与软件缺陷

本轮实际使用 1 次候选启动、1 次原 BOOT 回退、0 次 SDK。候选运行 ID 为 `6c310b81-6acc-4287-bc23-a8d2fc66d499`。串口实际接收标记、候选 BOOT 全量读回和回退文件核验均已通过。

第一次采集在旧六路监视器 ARM 阶段停止，尚未向新增控制接口发 SNAP：

| 观察对象 | 实际原值与含义 |
|---|---|
| 旧监视器，写命令前 | status=0，request=response=0 |
| 软件写入记录 | 对映射地址 0x400b0400 调用一次 `struct.pack_into('<I', page, offset, 1)` |
| 旧监视器，失败后只读 | status=2（命令错误），request=response=1；ARM 已完成确认，但错误位置位 |
| 新增控制接口，只读 | ABI=0x48444301，status=0，request=response=0；未发 SNAP、CONS 或 CHKR |
| 独立只读波形／原生检查 | 两个波形 bank 均未触发／发布；原生强制协议窗口未触发，仅记录 READY 复位建议 92/93/95 |

采集器错误文案把所有拒绝条件统称为“uncertain/failed/100ms deadline”。本次从写入记录到失败约 3.6 ms，不能称为实际等待了 100 ms，更不能称为新接口 SNAP 超时。

原因已定位至该软件写入方式不满足单次寄存器写的契约。[CPython 3.8.10 源码](https://github.com/python/cpython/blob/v3.8.10/Modules/_struct.c#L1655-L1729)的 `s_pack_internal` 先清零目标缓冲区，再调用数值打包；对设备 mmap 使用该函数会带来额外写入风险。已在板端同版本 Python 的普通 bytearray 中复核：初值 `a5a5a5a5`，数值转换过程中已变成 `00000000`，最终为 `01000000`，全程 MMIO=0、SDK=0。这与“零命令触发错误位、随后 ARM 被接受”的寄存器现象一致；没有逐拍采到这次 GP 写总线，不声称已经观察到确切 AXI 写拍数或写宽度。

旧监视器没有完成 FREEZE，不能将该次采集当作完整健康启动准入。独立只读窗口未触发，也不等于各组件功能通过。本轮没有消费、图案、AI 推理或屏幕显示验收。原有 D45 异常不能归因于这次新采集器问题。
