## 启动固件静态分析与当前阻塞

使用本机既有AArch64 GNU objdump读取未改动的FSBL／BL31。FSBL正常控制流为`__cmain → __iar_data_init3 → main → BootInitialize → SystemInit → ps_init`；IAR初始化器把`0xfffe9ba8`的`0x32a0`字节复制到`0xfffe6908`，五组PS表均在该目标范围。复制源与原BOOT相应字节完整一致；表内非零操作按MIO、PLL、clock、DDR、peripherals顺序传给`ps_config`。**ELF加载映像中的零值是运行时复制前的占位，不能认定PS未初始化。** [实际表、字节对应关系和限制](startup-ps-runtime-tables.json)、[本机原生反汇编](startup-reset-disassembly.txt)、[C运行时复制证据](startup-c-runtime-init.txt)。

当前固件使用`0xe0026000`区域，已有A7 BSP的`0xc000b000`定义不能套用。BL31系统复位函数只能确定静态指令，不能证明其覆盖HP2／FIFO或DDR事务状态。当前缺与FMQL30TAI、AArch64、FSBL4.51／030ai匹配的BSP或厂商HP2／FIFO复位接口，用户确认目前没有相关资料，将向比赛官方咨询。取得契约前不猜复位位、不改FSBL、不注入RREADY排空未知响应；原BOOT保持运行。没有当前资料时，仅增加PL延时或门控不是有根据的根因修正。

## 本轮实施前离线确认的事实

1. **RCOUNT／RACOUNT不能用于当前器件的PS FIFO占用诊断。** 原厂030ai适配的`PS7_wrapper`把对外`SAXIHP2RCOUNT`固定为`8'h00`、`SAXIHP2RACOUNT`固定为`3'b000`。原语同名8＋3根引脚被重新用于NPU的`pl_awdata`，不是对外FIFO计数。11位的逐项映射及源文件见[source-contract.json](source-contract.json)。r25曾把这两组端口列为下一候选观测方向，本轮撤回该候选解释；其物理存在不代表FIFO语义成立，读到0不能证明FIFO为空，也不能改动原NPU映射来恢复通用PS7语义。
2. **PS端HP2复位输出真实存在，但未纳入现行设计的复位就绪判断及观测。** 适配`PS7_wrapper`仍把原语`SAXIHP2ARESETN`接到上层输出；生成的PS顶层未导出该输出。实际r24 routed DCP中，该原语输出无网络、无下游。r24修改的是`proc_sys_reset_1.dcm_locked = ddr3_init_done & ~ddr_ui_rst`，保留的PL互联复位链并未等待这个PS输出。它是PS输出状态，不能向该端口注入复位，也不能据此直接认定内部FIFO已清空。
3. **此前时钟名称疑点已由实际布线消除。** 原厂Liberty将被复用的计数引脚时序关联到`AI_CLK102`；实际DCP中`SAXIHP2ACLK`与`AI_CLK102`均为同一`clk_pll_i`网络。因此不能只根据两个名字推断存在额外时钟域。实际原语数据引脚的NPU寄存器扇出亦与RTL映射相符。
4. **FSBL没有变化，但仅凭未变不能认定PS FIFO已复位。** 原BOOT的AArch64 FSBL中`ps_init`静态直接调用`ps_config`五次，见[原始静态调用解码](fsbl-ps-init-calls.json)。这只证明调用目标，不能证明具体寄存器时序或内部FIFO效果。本机另有A7系列BSP的`0xC000B000`等定义，与本任务AArch64启动环境不相同；不据此或通用Xilinx地址读写当前PS复位寄存器。当前没有可核实到该器件／固件的独立PS FIFO状态寄存器契约。

本轮只读检查使用Vivado2018.3＋现行030ai／JFM，打开已通过的r24实际布线检查点，原生退出0、约112.3秒，无重新综合／布局布线、约束修改或位流生成。[原生命令](inspect-physical.tcl)、[原始结果](physical-ps-facts.tsv)、[紧凑结果](physical-summary.json)。PS原语HP2 RVALID／RID仍按实际HP时钟定义；FIFO名引脚的复用不能扩展成“整个HP2接口均无效”。

## 最小观测候选及实现约束

- 保留同一r24功能逻辑、DDR就绪门、四处互联ARESETN及原模型／SDK／NPU映射。只把真实PS `S_AXI_HP2_ARESETN`通过生成PS模块、BD和wrapper显式导出到被动观测器，不接管功能复位。实际选择保留原厂PS OOC并导出既有输出网，253个单元不变、端口增加1；最初PS RTL重建产物保留但不使用。顶层修正PJTAG重复OBUF集成问题，保留原厂PS内部OBUFT。
- 增加以100MHz GP为共同基准、配置后开始且跨本地复位保留的64位计时。经明确同步链观测PS HP2复位、PL互联复位、GP／HP复位、FCLK_RESET0_N、DDR ui_rst／校准、PS与HDMI ARVALID／RVALID以及HP时钟活动见证。保存初态、首个／最后释放时刻和有界事件表；事件满后置溢出，关键首事件不得因日志满而丢失。
- GP时间表保存的是同步后的管脚电平和变化，不能作为AXI事务计数。两个同步后的事件若相隔不足3个GP周期，只报告顺序未分辨；HP事务数和RID／RRESP继续取原104字及19字历史。首异常事件另保留完整源域周期扩展值，避免r25的32位模时间无法还原。GP发布与HP FREEZE不是同一物理边沿，切面分别标明。
- 旧`0x400b0400`的104字及19字协议保持。新观测采用独立只读诊断窗口`0x400b0600`，实际解码及回归已核对无冲突，不提供功能复位／RREADY／START控制。快照只随既有FREEZE发布，保存运行ID、ABI、完整原值及前后代数；不新增SDK依赖。
- FIFO直接占用标为“当前不可观测”。使用现有AR／R历史只能给出已观测请求与返回的相容性，不能把协议计数差等同物理FIFO深度、把零计数当空队列证明，或用假RREADY排空未知响应来掩盖问题。

当前记录器另在HP源域保留8组原始读／写握手计数和首事件，避免GP漏掉短脉冲。初始已高只记为初态，不冒称观察到复位释放边沿。HP活动由分频心跳经同步后判断，255个GP周期无变化才记失活，不能分辨更短停钟；GP与HP快照切面不同，首R的原始状态位也不能当作同步一致向量。事件表16项，溢出保留专用首事件并停止第二候选，不覆盖配置前或观察时钟尚不存在的活动。

离线门：定向仿真覆盖PS先释放、PL先释放、HP停钟期间PS复位、复位期原始RVALID、无AR异常返回、事件接近／溢出及本地复位保持；核对PS输出确实接到观测输入，计数假端口仍未作为观测源。完整实际目标布局布线后复核setup／hold、时钟、内部未约束路径、DRC、旧保持总线与新增同步／保持路径；不新增false-path、频率或DRC例外。通过后才生成实际bit，复用现行ICAP／BOOT封装并核验非PL字节不变。

## 板端执行范围与判读

## 对精简PL构想的接线核对（2026-10-20）

当前候选是从原厂参考工程源码／网表保留适配基线后重新综合、布局布线生成的自定义bit，不是在原bit二进制末尾附加HDMI。实际HC0→HP0、HC1→HP1、HC3→HP3；HC2与HDMI经S00／S01共享HP2，不能把全部SDK参数／权重搬运概括为只走HP2。删去视频输入不自动空出AI已有HC端口，也不自动把HDMI移出HP2。

精简方向有价值，但r25已经在SDK／DMA／HDMI START之前捕获故障，当前不能归因为NPU与HDMI同时传输时带宽不足。另有未被此前读观测覆盖的活动：实际`frame_to_ps_largebuf #(.CANDIDATE_SCANOUT(1))`仅关闭旧读请求／读使能／RD_START，写请求及AW／W／B仍接HP2的S01；`frame_trans`同时驱动共享soft_rst。应在下一被动时间轴中补充旧视频写侧与PS侧AWVALID／WVALID／BVALID、复位及首事件，结合实际HP时钟统计握手；未加载SDK并不等于已证明无视频写事务。AXI写活动本身不构成读返回异常的因果证明。

精简版作为后续独立对照候选，先做依赖清单：可考察删除旧视频输入、旧视频读写／缩放及不用的外设链，保留PS、NPU/AI_Mate、PL DDR/MIG、四路HC、有效时钟复位及SDK必需的寄存器／复位语义。先隔离一个旧视频总线主机对照，再批量裁剪；同一轮不叠加HP端口重分配和NPU配置变化。单次未复现只能认定该次对照，布局变化也可能改变偶发性；取得源级关联及重复证据后才能认定修复。本次咨询未被解释为立即批量删模块或重分配NPU通道的批准。
