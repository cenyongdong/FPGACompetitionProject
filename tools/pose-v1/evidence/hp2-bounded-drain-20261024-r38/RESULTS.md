# r38：启动异常返回的有界消费实板验证

2026-10-24。**本次确实复现了启动异常，并通过有界消费接收完 16 拍返回，两侧 RVALID 随后降为 0。它证明本次异常可以被消费掉，尚不能证明启动根因已修复或正常读帧已经恢复。** 已完成一次候选启动和一次原 BOOT 回退，批次关闭，余额为 0。

## 设计与本次改动

PL 作为 AXI 主机读取 PS DDR。AI HC0→HP0、HC1→HP1、HC2→HP2 S00、HC3→HP3 保持；HDMI reader 位于 HP2 S01，旧视频写分支仍保留。FSBL、PS 配置、功能复位、频率和 AI 四路连接均未改变。

仅在原 S01 reader 的 RREADY 之外并入一次性诊断接收使能，接收的数据直接丢弃，不写像素 FIFO。诊断没有 AR／AW／W、功能复位、SDK 或 HDMI START 输出。等待 PS_HP2_resetn、PL_HP2_resetn 都为高且 HP_reset 为低后运行；最多接受 256 拍或运行 4096 个 HP 周期。连续 64 周期无 S01 RVALID 就结束；发现请求、reader 接收、复位变化或错误本地 ID 则停止。结束后不再自动接收，QUIET 后再出现 RVALID 会留下 sticky 标志。

诊断的 QUIET 只表示观察到安静窗口，不是“接口恢复完成”许可。没有清除原生协议检查历史，也没有自动开放业务。

## 实板关键现象

监测启动后的累计 PS AR 握手为 0，PS／旧视频 AW、W、B 握手也为 0。两段连续采样中，PS、S01、HC2 均未出现 AR 握手，HC2 没有接收 R 数据。

| 事件 | 实际 HP 周期 | 含义 |
|---|---:|---|
| PS_HP2_resetn 首次观测到变高 | 342596 | 此时 PL HP2 互联仍在复位 |
| PS_RVALID 首次变高 | 342598 | 比上述边沿晚 2 个采样周期；此前无观测到的 AR 握手 |
| PL_HP2_resetn 释放 | 11586112 | 开始满足诊断运行条件 |
| S01 诊断 RREADY 拉高 | 11586113 | 开始允许丢弃接收 |
| PS 接受第 1～16 拍 | 11586114～11586130 | 中间有 1 周期背压；第 16 拍 RLAST=1 |
| PS_RVALID 拉低 | 11586131 | PS 边界不再提供这批返回 |
| S01 接受第 1～16 拍 | 11586118～11586133 | 第 16 拍 RLAST=1，与 PS 侧拍数一致 |
| S01_RVALID 拉低 | 11586134 | 返回缓存已送完这批数据 |
| 诊断 RREADY 拉低并结束 | 11586198 | 连续 64 个无返回周期后进入 QUIET |

16 拍全部为 PS RID=0x20、S01 本地 RID=0、RRESP=0、RDATA=0；第 16 拍在两侧都有结束标记。PS 的 16 次接收、S01 的 16 次接收以及诊断计数三者一致。按 64 位数据宽度，共丢弃 128 字节。

诊断状态为 `0x02055082`：QUIET，接收 16 拍，运行 85 个 HP 周期（名义 425 ns，包含安静确认时间），看见 RLAST，没有 RRESP 错误、错误 ID 或迟到返回标志，未达到拍数／时间上限。首次软件快照时 PS_RVALID、S01_RVALID 均为 0；其 GP 冻结计数为 6940073930，按 100 MHz 名义频率对应约 69.4 s。

原生协议检查仍捕获规则 58（RDATA_NUM）、59（RID）；首次建议指示在 HP 周期 342601，首次强制规则指示在 342603。消费结束不抹去启动时已经发生的无匹配请求返回问题。

## 对方案可行性的判断

**有收益：** 本次不是异常未复现，而是在已捕获启动 RVALID 异常后，实际消费到一个以 RLAST 结束的有限 16 拍序列，并看到两侧 RVALID 拉低。这支持把“启动期受限丢弃”继续作为候选缓解方法研究。过去只放行 6 拍后被下游背压的现象，不代表异常源只有 6 拍；本次打开 S01 接收后得到了完整的这批返回。

**不能直接当正式修复：** 只有一次候选启动，不能保证其它启动也固定返回 16 拍；没有匹配 AR，仍不能判定这批数据的来源、复位前后事务归属，以及适配接口内部记账是否恢复一致。看到 RLAST 或一段安静时间，也不足以证明下一次合法读请求一定能得到正确数据。不能据此推断 PS 内部 FIFO 的位置或深度。

下一步应先设计有界、可比对的合法 DDR 小读回验证，检查地址、ID、长度、RLAST、数据和后续停止条件，再决定是否把此机制纳入启动流程及恢复 AI／HDMI 联合测试。本包未加载 SDK、未执行 DMA／推理、未发出 HDMI START，也未开展长期验证；D45 保持开放。
