# HP2 原生协议检查实板结果（2026-10-23，r32）

本次复用 r31 已完成布局布线并生成的协议检查位流，进行一次候选启动及一次原 BOOT 回退。候选正常启动，本次未复现此前“PS HP2 复位输出首次变高时，RVALID 同拍变高”的异常。取得实际板内 BRAM 波形；检查窗口内只有 READY 复位建议项，没有强制性协议错误。单次健康启动不能认定偶发故障已修复，D45 保持未解决。

## 实际设计与测试条件

目标为 FMQL30TAI，采用现有 Vivado 2018.3＋复旦微 030ai/JFM、Procise 适配流程。该位流完整布后 setup WNS +0.018 ns、hold WHS +0.001 ns，TNS/THS 为 0；107,659 条可布线网络全部完成，无布线错误。沿用原 AI 两项既定最小周期例外，没有新增时序例外或 DRC 豁免。

AI 的 HC0→HP0、HC1→HP1、HC2→HP2、HC3→HP3 保持原连接。HDMI／旧视频对应的 HP2 互联 S01 主机输入继续置零，双输入互联与模块仍保留。此次未调整功能复位连线、频率、PS 固件、模型或 SDK；BOOT 中 PL 区之外的字节与原 BOOT 相同。

原生 AXI Protocol Checker 2.0 Rev.4 旁路观察 HP2 PS 接口的 AR/R/AW/W/B 五通道，AXI3、地址32位、数据64位、ID6位，读写未完成突发容量各8，与实际互联配置一致。检查器 ARESETN 取自所观测的 PS_HP2_resetn。完整输入束及 ARESETN 同步寄存1个 HP 周期；实际 AXI 功能通路不经过这些寄存器。原始波形直接采样上游信号，状态指示另外包含原生 IP 的内部流水延迟。

检查器独立完成初始化；本次触发时 PC_system_resetn、PC_checker_ready、PC_seen_reset_low 均为1，确认检查器就绪后曾观察到所接 ARESETN 为低。但这仍不能代替厂商对该 PS 复位输出覆盖范围的说明。

未调用 Device::Open，未发起 DMA、推理或 HDMI START，没有按键操作。连续波形及协议结果通过只读 CSR 取回；旧诊断监视器仅执行其计数 ARM/FREEZE，不启动功能业务。

## 捕获到的关键时序

协议窗口为 HP 周期342437–342564，共128个连续上升沿样本；名义每点5 ns。首次原生检查指示在342469周期，保留前32点与后95点。

| HP周期 | 实际原始引脚／状态 |
|---|---|
| 342437–342463 | PS_HP2_resetn=0；AWREADY/WREADY/ARREADY=0；ARVALID、RVALID、AWVALID、WVALID、BVALID均为0 |
| 342464 | PS_HP2_resetn与AWREADY/WREADY/ARREADY在同一个采样点变为1；RVALID保持0；PL_HP2_resetn仍为0 |
| 342469 | pc_status首次非零，置位92、93、95；原始RVALID仍为0 |
| 342498 | HP_reset从1变0；PL_HP2_resetn仍为0 |

完整160位首次状态为 `0x0000000000000000b00000000000000000000000`。窗口内状态仅包含：

- bit92：XILINX_AWREADY_RESET。
- bit93：XILINX_WREADY_RESET。
- bit95：XILINX_ARREADY_RESET。

以上按原生检查器定义归为复位期间 READY 的建议检查，不能当成强制 AXI 协议错误，也不能据此定位为 PS 故障。窗口内五通道握手数全部为0，无检查器容量溢出。RVALID=0时的RID、RLAST、RDATA不作为有效返回解释。

原来的“首次 PS RVALID”窗口没有触发，不能为它生成波形。“PL 互联 resetn 首次为高”窗口正常发布128点，范围11578188–11578315，释放点为11578220；PS、S01、HC2 的 AR/R 握手全部为0，RVALID保持0。启动累计监视器同样未记录PS AR/R或写通道握手、首次PS RVALID，计数无溢出，S01源端置零核验符合。

## 对照、限制及下一步

r30 故障样本在 PS_HP2_resetn 由0变1的同一 HP 采样点观察到 RVALID=1，之后 PL 释放窗口存在6拍 R 握手而累计 AR 为0。本次 r32 在对应释放窗口中 RVALID保持0，属于一个健康启动对照。两版诊断硬件不同，不能用这一次对照证明协议检查 IP 改善了启动可靠性。

当前协议缓冲由“首个任意原生指示”触发，建议项也会触发并冻结；因此本次协议窗口在早期 READY 建议出现后结束，不能声称覆盖了之后完整启动过程中的全部检查状态。PL 释放由另一连续窗口覆盖，启动计数器只提供其各自覆盖范围内的累计信息。配置前、HP停钟期间以及两个连续窗口之间的逐拍行为仍不可见。

后续重点是取得异常启动时对应的原生检查状态，比较 RVALID、AR 历史和复位释放关系。若继续改进诊断，可将首个强制协议规则指示单独作为触发，并另存建议项，避免 READY 建议过早占用唯一协议窗口；无需据此立即改动功能复位或 AI 分配。本轮不追加启动或功能负载。
