## 首次坏读的直接证据与边界

本轮只离线比较已保存的 r53 数据，没有恢复旧 DATA 调查：

- op192 input1 的 4200 个 FP32 索引字中，1568 字全部逐位等于同帧 input0 姿态数据的相同偏移；其余 2632 字与本帧 Host TopK 展开一致。
- 首次 owned Host、即时 post-copy 副本、近期保存副本逐位一致，错误先于后续 CPU Gather。
- 两轮公开 `Tensor::read` 晚读均得到正确索引；input0 各版本不变。晚读没有覆盖或修补首次坏值。
- 近期 181～187 七次索引副本均与各自 TopK 一致。

完整比对见[index-read-analysis.json](index-read-analysis.json)。源为 `AXIZG330AIPLDDRMemRegionNode`，input0 地址 36827136、30240 字节，input1 地址 36806656、16800 字节，两块源区间与 Host 目标均不同；HDMI 帧在另外的 PS UDMA 区间。现有证据确认首读内容混合，但不能区分源端瞬态、SDK 搬运/可见性、共享传输通路或其它环节，也不能把本次错误直接归因为 HDMI/HP2 仲裁。

下一步应先核实当前公开 SDK 读取路径的完成与可见性契约，再设计保留首读原值的最小对照；不能用晚读替换、固定延时、索引修正或放宽数值门绕过错误。当前没有新的板测额度，不自动重跑失败 SDK。
