# replace_7z030ai_file的真实作用与当前版本边界

2026-10-15，按用户提示实际核对本机JFM_Kits。使用现有Vivado2019.1的正常Tcl source加载器，在新英文目录读取同SHA的all_src_files.tcl，加入只读文件、外部命令、库加载与项目/配置变更拦截；只提取真实过程定义，未调用replace_7z030ai_file、reset_database_to_default或hook。r2加载exit0、3.141304秒/60秒预算，未触发任何变更拦截。r1中文路径编码/主机日志编码失败保留，不回写。

## 实际函数体说明

1. 入口取得Vivado安装路径，并明确检查版本必须为2018.3；其它版本抛出`This command only support in Vivado2018.3!`。不能依据函数尾部未必可达的2022.1分支宣称支持2022.1，也不能删版本判断后套在2019.1。
2. 先调用reset_database_to_default。该辅助过程静态列出36个不同目标路径，涉及多个器件族的原库恢复及标记删除，因此整个命令的影响范围大于下面9项030AI替换。
3. 正常speed=0路径从ip_patch/030ai替换以下Vivado安装目录文件：Sitemap2.xml、unisim_comp.lib、unisim_comp.v、zynq.lib、zynq.rtd、zynq.xng、zynq.padr、xc7z030.paspd及unisim.btl。不仅是时序数值，也覆盖原语定义和器件相关数据库。
4. 当前2019.1对应9个目标均存在，但全部与030ai配套源SHA不同；该事实不证明可以互换。fast分支所需xc7z030ai_fast.paspd在本机030ai目录不存在，不能自动启用fast。

完整函数体、辅助函数、当前安装目标/030ai源身份与准确路径分别保存于本批r2过程快照及r1 replacement-review.json。没有替换、恢复或修改任何安装文件。

## 对当前PS错误的意义

这条线索支持应核对30TAI专用原语/器件配套，而不是只看普通PS7 IP版本。本次进一步审查实际报错位置processing_system7_v5_5_atc.v:5420：PS7_inst有4527个唯一命名端口，其中AI_IN2942、AI_OUT744，另外还有AI_CLK等扩展。原生Procise报其绑定PCPU7端口数量不匹配，确有接口定义不一致。

但此命令写的是Vivado数据库，并没有直接修补Procise的PCPU7定义；尚未读取/逐端口核对原生PCPU7完整声明。不能断言运行这个命令就能修复Procise，也不能凭数量去删端口或猜映射。PS配置/自定义包/AI_Mate保持。

当前常规安装目录核对只发现D:/Xilinx/Vivado/2019.1；未发现2018.3安装。现有授权仍是不安装/升级工具、不改全局数据库；此次“参考命令”按只读审查执行，未将提示扩展为运行全局替换的授权。

## 工程内单文件读取的补充门检

另外用当前2019.1仅在新工程内读取030ai/unisim_comp.v，未调用替换函数。单独将PS7原语作为RTL顶层，工具22.559951秒exit0，但报告empty top且可见端口0，metadata-review.json明确判端口门检未通过，不能当硬件成果。
