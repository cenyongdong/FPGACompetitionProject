# 不同输入同输出问题已解决：r6实板工程验收

## 工程内容总结

用户将当前问题所有执行交由代理后，代理完成运行库审查、FPAI交叉编译、SFTP传输、Lite各阶段测试和完整回传核验。
当前固定308/309/310及同Session重复308范围内，“不同CSI得到全部相同输出”的故障已解决。
构建、Host107/内容、离线、SDK内存、Session apply、单样本、三样本工程门检均通过；数值容限和持续性能分开验收。

### 根因与修正

r5实测首次前向计数0→745，第二帧却从745开始并累加到1222，后两帧仍1222。
匹配ARM SDK的ZG完成检查使用本帧固定阈值223/234/477/481/638/720/745，旧计数提前满足这些阈值，导致读取旧结果并提前握手。
Caller/Input0实际内容每帧正确，五个CPU适配内核对收到数据的52000个值也正确，问题在跨帧执行状态和完成判定。

仅修改独立mixed_check.cpp：每帧在已确认上一帧完成后调用官方Device::reset(1)，确认执行计数0，再使用同一Session前向；
返回后检查两个输出waitForReady和最终计数745，才能进入下一帧。
reset(1)为官方FPGA状态清理路径，未进入reset(0)的FPGA/NPU全复位路径；不直接写寄存器。
CPU内核/Gather、桥复制、预处理、融合、SDK库、模型/RAW及BOOT保持，Matmul仍走NPU。
[源码来源与适用边界](MIXED-FRAME-STATE-R6-SOURCE.md)及[唯一构建源码变化](evidence/mixed-20261006-frame-state-r6/source-review.json)可复核。

## 对后续开发的参考

帧生命周期必须包含“上一帧完成→SDK FPGA状态清理→计数0→执行→计数745/输出就绪”。
当前固定745来自已核验七组同步基线；模型、SDK或融合改变必须重新核对，不能照抄常数到其他工程。
首次数据正确或回调齐全不足以证明跨帧消费新数据，保留实际内容、计数和重复样本能区分此类故障。
后续接入应用可复用已验证边界协议；现有原推理检查器仍保留，不直接运行旧程序替代r6。
部署数值容限依据本次实测另行讨论；HDMI/RTSP、持续5Hz/延迟和30分钟闭环仍未验收。
