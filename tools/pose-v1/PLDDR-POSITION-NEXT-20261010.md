# 下一对照：真实混合引擎运行，移除视频负载

## 选择与可行性

下一优先采用**原完整混合引擎、无VPU／显示／网络负载**的独立有限入口，控制视频并发因素并取得真实NPU生产的数据。使用现有`application::Engine`公共接口；保留单主线程创建／前向／销毁、模型／RAW／融合／六Host数学、原ready／reset(1)／745／profiling-off，以及192对象／计数／拥有shadow／原异常两晚源机制。

不抽取或改写ZG子图、不猜公共视图能单独运行某生产组，不包装绝对地址或更换复制API。公开layerCount234在旧失败已达到，不能据此增加无效等待或宣称DMA同步。

## 具体新修订门检

1. 新SDK无关有限窗口调度／输出保存适配，不包含其他模块.cpp或访问Engine私有状态。直接固定完整CSI Window的输入源，保留源样本身份和调用序号；输出完整100分数／100姿态先保存再比较。不上TCP、渲染、RTSP、VPU或HDMI。
2. 包和程序新身份，原数学与桥源码保持。原完整Host107可明确身份复用；新增SDK-free调度、失败后不再调用Engine、独立flush和窗口所有权Native／ARM实际验证。若源码／程序身份变化影响CPU实现，则必须重新Host107，不以旧结果代替。
3. 一次三窗308／309／310＋重复308有限回归（整体180秒，Engine初始化60秒）。输入／分数／姿态完整逐位已核板端参考，六Host／ZG回调及0→745协议核验；先保存原输出和拥有shadow，再独立比较。
4. 前门通过后一次有界103窗口，固定与旧103相同源列表及200ms目标间隔；不突发补帧，记录实际开始时刻／调用间隔，严格上限180秒，取证日志与原有限方式保持，不作低日志性能验收。每帧完整输出和参考、异常原暂存／两晚设备源、192元数据及原计数均保留。
5. 非有限／非整数／越界／输出失配、SDK异常／超时／OOM／新内核错误即停止，保存原错误和所有已完成数据，不重复制覆盖、不放宽比较、不重开设备。不自动执行原有视频103负载作“恢复确认”。

新程序隔离不同条件，不是重跑旧失败目录。内存规整如资源状态确有需要，按现有自主策略记录原因和完整前后现场；规整不作数值修复，不清缓存／重启或改CMA／BOOT。

## 结果判别与限制

- 无视频的真实引擎若复现，视频并发不是该次故障的必要条件，可继续定位真实NPU生产／SDK搬运及Host目标；仍不能仅按坏块像前次数据就归因早读或缓存。
- 若103通过，说明本次无视频条件可完成，但图解析、分配和调度不同，不能认定VPU为根因，也不能回填旧并发失败为已修复。下一才设计同身份视频负载对照或经实测支持的最小修正。
- 不按一次103宣称永久可靠或连续5Hz／30分钟通过。SDK自有较高地址和公开块归还证据独立保留；真正映射／零拷贝需另验应用CPU地址、DMA/MMU/cache／寿命契约。
