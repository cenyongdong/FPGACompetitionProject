# 原epoch442的100-query与迁移第50轮180-query对比

2026-10-23，Asia/Shanghai。结论：在相同测试集、`score > 0.2`和相同匹配规则下，第50轮180-query在1、2、3人组的数量不足、多报、疑似重复、两列MPJPE及空间召回率均出现退化。该结论针对这两个具体checkpoint，不代表100轮结束后的最终结果，也不能将退化单独归因于query数量、取消TopK或某一项权重迁移。

本报告所有箭头均为 **原100-query epoch442 → 新180-query epoch50**。

## 计算范围与一致性

- 完整测试集7,824帧：1人2,586帧、2人3,184帧、3人2,054帧。逐帧样本顺序及全部GT与上一轮180-query分析严格一致。
- 原模型使用`result/code_faithful/petr_wifi.py`及`best_mpjpe_epoch_442.pth`，全部参数严格加载，人体query为100，入口、出口TopK均保留；原生`simple_test`逐帧batch1。
- 100-query当前共享joint推理优化与逐候选计算在3份真实样本上核对：分数逐位一致，姿态最大差`2.384185791e-7`，未更改其权重或结构。
- 本次仅CPU两线程、低优先级评估，耗时421秒。正式训练监督器及torchrun PID／创建tick保持，分析结束时仍在第57轮且loss／query／joint梯度有限；没有占用训练GPU、停止进程或更改训练配置。
- checkpoint身份与统计定义分别见[原100-query完整统计](../analysis-original100-epoch442-r1/summary.json)、[180-query完整统计](../analysis-epoch50-counts-r1/summary.json)。

原口径从各自全部100／180候选中借助GT作原有贪心匹配，随后平均逐帧MPJPE。阈值候选匹配MPJPE则先保留`score > 0.2`，用Hungarian一对一匹配后平均实际配上的人体对；没有距离合格门限，也不直接惩罚未配对真人或多余候选。这两项必须结合数量和空间覆盖统计解读。原口径的候选池大小本身也有差异，不能把它作为唯一效果指标。
