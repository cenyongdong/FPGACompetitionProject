# 180-query、无TopK、共享joint decoder修改方案

日期：2026-10-22。用户已批准epoch442迁移训练100轮、180组query全部重新初始化，并指定GPU1、6及每90分钟监督。方案已实施，实际验证、训练与恢复状态唯一维护于[STATUS.md](STATUS.md)。

## 目标与数据流

将当前2024版共享细化模型作为独立新模型分支，pose decoder使用180个query，删除入口和出口的两个TopK及相应候选索引选择。180个pose结果全部直接进入共享joint decoder，输出保留原始query顺序，不按分数重排。

```text
预处理CSI [B,180,60]
  → 特征投影、6层encoder → memory [180,B,256]
  → encoder姿态提案 [B,180,42]，保持token原顺序
  → 3层pose decoder，180组可学习query，无TopK／候选Gather
  → 分数 [B,180]、粗姿态 [B,180,14,3]
  → 2层共享joint decoder：每个输入只计算一份14关节特征
  → 将该输入的关节偏移广播加到全部180份独立参考姿态
  → 分数 [B,180]、细化姿态 [B,180,14,3]，无排序／截断
```

这里180是人体候选数量，joint decoder的关节query仍为14。共享权重及同一输入的特征计算，不把180个人体候选合并成一个姿态；不同输入之间不得共享memory、偏移或随机状态。

## 模型修改

| 位置 | 修改内容 |
|---|---|
| 配置与query embedding | `num_query=180`；提案数量与实际encoder长度均为180；embedding为`[180,512]`；配置检查实际输入维度，禁止静默截断或补候选。 |
| encoder到pose decoder | 直接使用全部`enc_outputs_kpt_unact`作为reference，保持现有detach边界；删除TopK提案选择及按其索引执行的GatherElements。query索引i对应原始token索引i。encoder分类头及其训练监督保留。 |
| pose decoder出口 | 单类别分数直接sigmoid，180份分数与姿态一一对应；删除`_get_bboxes_single`及导出包装器中的TopK、排序、候选重排与100候选截断。 |
| joint decoder | 用`[14,B,256]`关节特征和`[180,B,256]`memory计算，每个输入独立运行一次；参考姿态保留`[B,180,14,3]`。偏移以`[B,1,14,3]`广播，各层reference更新及detach语义沿用原模型；使用非原地加法，避免广播写入及ScatterND。 |
| 训练与梯度 | 训练也走每输入一次的共享特征路径，不再按正候选复制memory。共享计算意味着同一输入的候选使用同一份dropout结果，这是新模型训练语义的一部分；不为“共享”直接关闭dropout。 |
| 监督与匹配 | pose分类监督覆盖全部180候选；保留原Hungarian匹配、encoder／pose辅助损失及其系数和归一化公式。joint decoder产生全部180份细化结果，坐标损失只使用匹配到真人的候选与有效关节。按输入／query维度定位目标，不沿用固定100的除法和reshape；保留粗姿态detach。 |
| 边界情形 | 覆盖多输入、同一输入多人、不同输入正例数量不同、零正例；零正例时产生有限零损失并保持DDP图可执行，不伪造真人标签。 |

现有共享优化只在`eval`且单输入时启用；不能只修改两个配置数字后继续使用当前训练路径。训练、验证、原生推理和ONNX包装器均须接入上述新分支。

## 验收口径

- **结构**：180候选贯通，模型无两个TopK及候选排序／截断；共享joint特征确实每输入只计算一次，分数与姿态保持同槽对应。
- **训练正确性**：真实输入下损失／梯度／参数有限，匹配与多输入身份正确；发生OOM、非有限值、非法索引或逻辑错误先保存并停止受影响负载，不自动重试。
- **精度**：按原测试集报告原口径MPJPE，同时明确180候选给GT辅助匹配带来的搜索空间优势；补充基于置信度的选择、人数分组和粗／细化比较，不能仅凭180候选中挑最佳的误差下降认定部署精度改善。
- **性能与稳定性**：24ms属于旧100-query图，新模型耗时须后续实际测量。删除中间交接可能降低D47出现机会，但不证明DMA／缓存问题根治。
- 原模型的逐位分数和3mm门禁不能直接用于新训练模型；后续建立新模型自己的FP32参考及量化验证规则。旧D47原始失败、旧DATA暂停和HDMI长期边界保持。
